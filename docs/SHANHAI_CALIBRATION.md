# 山海新版敌人首轮校准报告

生成日期：2026-09-22

本报告记录 34 套固定敌人的首轮五维校准，以及校准后的固定输入回归。它是内部校准记录，不是全面平衡结论。精确的逐实体原参数、现参数、差值和每条样本记录分别保存在：

- `verification/shanhai/calibration-summary.json`
- `verification/shanhai/calibration-encounters.json`
- `verification/shanhai/calibration-runs.json`

## 输入与可追溯性

- 固定参考遭遇：34 个敌人 × 5 门开局功法 × 5 个遭遇种子，共 850 个样本。
- 参考盘是离线固定输入：每个敌人直接使用内容源 authored 的 `n`，不模拟运行时节点成长、奖励或路线状态；早段、后段、精英和首领只是报告分组，不是另造一套现场境界。
- 玩家与敌人均以 `calculateStats()` 得出的最大气血满血入场；玩家不额外加入法宝，敌人使用内容库中的实际天赋与法宝。
- 战斗使用真实 `simulateBattle`，单战上限 256 轮，没有 mock 战斗。
- 真实流程单独统计：真实 `ShanhaiGame`、`tests/shanhai-policy.mjs` 和真实节点输入，5 门开局功法各使用 `acceptance-0` 至 `acceptance-4`，共 25 局；路线按种子索引轮换 `avoid`、`steady`、`tracking`。
- 遭遇输入哈希：`563f83c0552c7197fb82624f651d484e8856969b45452e2c9ad1169bc446c223`。
- 真实流程输入哈希：`72d884737d1567958e472e2b09652c43fb57cd15d17da79ab8fc74ba19f1f54c`。
- 遭遇种子格式为 `calibration-<enemyId>-<method>-<index>`；真实流程使用五个固定 `acceptance-*` 种子，每个开局功法各跑一次。完整种子和固定盘矩阵均写入上述 JSON。
- 34 套敌人的 `balance.measured` 仍全部为 `null`。本轮只记录 `design_target` 和回归观测，没有把模拟结果写回内容源。

### 目标字段边界与风险

`rounds` 是本报告直接观测并汇总的指标。内容中的 `net_hp_loss_pct` 与 `burst_warning_pct` 仍是设计目标字段；本次报告没有把它们提升为实测值，且所有敌人的 `measured` 继续保持 `null`。因此，净损血、最低血线和单轮峰值只能作为本轮固定输入的观测，不代表全构筑空间已经满足目标。

当前值得后续实测关注的是：

1. 第三幕首领和两个终战敌人明显偏快：固定参考盘的轮数 p50 分别为 4、6、7，而目标下限为 8、10、10。
2. 首领档位的净损血尾部最宽：p90 为 26.2%，全样本最高 54.8%，最低玩家血量最低到 282.4；不能只看全部胜利这一项。
3. `EN-A1-B1` 的 p90 净损 47.5%、最低血量 282.4，`EN-A3-C1` 的 p90 净损 22.0%，应在真实法宝和更多路线中复核。
4. `EN-A4-L1` 已不再出现固定盾墙平局，但其中位数净损仍低于精英目标下限；它的恢复和短时减伤需要真实流程样本继续观察。

这些差距暂不直接回写新的敌人参数：当前样本是固定种子、固定参考构筑、无玩家法宝的首轮回归，不能代替完整构筑空间的平衡判断。

## 复跑命令

```bash
npm run build
node tests/shanhai-calibrate.mjs
node --test tests/shanhai-encounters.test.mjs
npm run test:content
```

`node tests/shanhai-calibrate.mjs` 默认使用 5 个真实流程种子和 5 个遭遇种子；可用 `SIM_SEEDS` 与 `CALIBRATION_ENCOUNTER_SEEDS` 调整样本数。校准器不逐指令读档，完整主回归仍以真实 `ShanhaiGame` 流程为准。

## 当前边界

- 这是固定种子、固定参考构筑和有限真实路线的首轮校准，不是全法宝、全事件、全路线和全随机空间的平衡结论。
- 全部固定样本和真实流程样本均胜利，不能据此宣称胜率目标已经验证；第三幕首领、终战偏快以及首领血量尾部仍是主要风险。
- `measured` 全部为 `null` 是有意保持的内容约束；在有真实测试结果前，不应把本报告数字写回 YAML。
- 本报告位于 `docs/` 根目录，不在文档站公开根 `docs/shanhai/` 内，因此不会被文档站自动发现或发布。
