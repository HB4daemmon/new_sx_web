# UI Review 2026-09-18

## Release Contract

This review covers the UI release on top of gameplay/content version `4.4.0`.
The UI revision is `18.1`. The build contract is synchronized across
`src/presentation.ts`, `data/presentation.json`, and the generated presentation
field embedded in `data/game.json`.

The release does not change balance, combat rules, event outcomes, reward
generation, early relic availability, boss mechanisms, battle previews, or
cross-run systems. The generated `data/game.json` change is the presentation
revision copied by the existing build step, not a gameplay data change.

## Scope

The review exercises the offline built UI with an independent Playwright
browser context. Covered surfaces include:

- qualitative character creation for all race, origin, and fate choices;
- map navigation, route scrolling, bottom navigation, and tracking clues;
- build cards, behavior summaries, ability details, character details, and
  source disclosures;
- battle playback, pause/continue, 1x/2x/4x speed, skip-to-settlement,
  deterministic outcome, simple/detailed logs, non-damage feedback, log
  history/follow-latest behavior, settlement contributions, Space,
  reduced-motion handling, and responsive combatants;
- rewards, replacement preview/cancel, shop, rest, locked and returning
  events, character tracking/clearing, and final echoes;
- horizontal overflow and common touch targets at 320, 360, 390, 430, and
  1440 CSS pixels.

## Implemented

The final UI changes include:

- Battle simple logs retain shield absorption, healing, conversion, dodge, and
  key actions instead of showing attack-only entries.
- Battle rows identify both sides, preserve stable resource labels, expose
  playback controls through ARIA, and keep skip as a playback-cursor action
  only.
- Battle logs preserve history while following new entries, provide a
  return-to-latest control, distinguish life damage from shield absorption,
  and list every observed source, including sources with zero direct output.
- Responsive layouts were checked at 320/360/390/430/1440 CSS pixels, with
  44px-class touch targets, safe-area handling, focus treatment, and reduced
  motion behavior.
- Modal focus returns to the visible originating control and retains its
  triggering `data-index` when multiple matching controls exist.
- Abandoning an event gift that opened a replacement prompt requires a second
  confirmation. The confirmed path calls the engine
  `cancelReplacement` operation only; it does not replay the run. Escape and
  backdrop interaction enter the confirmation, a second Escape returns to the
  replacement prompt, and the confirmation defaults to keeping the gift.

The three independent review findings were fixed and covered by regression
checks: pending-event cancellation no longer replays state, character-dialog
focus restoration keeps the visible trigger identity, and observed
zero-output sources are not presented as successful contributions.
