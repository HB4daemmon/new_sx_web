# 山海版文案与卡面验收

> 状态：写作提案与验收清单；不替代[COMBAT_RULES.md](./COMBAT_RULES.md)的共同规则。

## 卡面要让人读懂

1. 一张卡先写输入，再写改变什么、何时生效，以及消耗、次数或限制（没有就不虚构）。
2. 一张卡保留一个主要变化。直接增伤、加速积怒、降低怒耗、护盾、治疗和提高触发概率都算完整选择。
3. 取舍来自同层选一、行动时机、资源出口、节点风险和机会成本；不要求每张卡附副作用，也不要求每次至少损失一种东西。纯正面强化和拒绝机缘都可以成立。
4. 多数天赋直接强化现有能力或加快流转，少数天赋改变打法；按功法特色安排，不为凑转换数量增加条件和状态。
5. 重要条件、概率、次数、持续时间、替代和失效情形必须写在卡面；不把决定选择的限制藏在总规则或长段落里。

### 简易写法示意

以下只示范句式，不是三份分册中的实际节点：

- **普攻积怒提高：**普攻完成后获得更多基础怒气；未命中仍按基础动作结算。
- **怒技消耗全部剑势，造成多段伤害：**怒技先支付怒气，再一次性消耗当前全部剑势，造成多段伤害；多段仍是同一主动作。

## 功法与事件

1. 每门先用一句话说清普攻、怒技、行旅的核心，再写四层 A/B/C；后层只能读取基础动作、公共状态或已明确提供的输入。
2. 专用名词少而稳定；专属战斗状态至多一种，优先使用怒气、护盾、燃烧、中毒、虚弱、破甲、剑势、蓄运和昼夜等共同词。
3. 事件先给短场景，再给动词开头的选择；选项旁写即时所得、即时付出、战斗类型和下一次回访。拒绝、停步或不交易可以是清楚且有价值的选项。
4. 后续回响落到人物态度、路线压力、资源、功法方向或终局时机；不把未发生的分支写成隐形承诺。
5. `示意`、`候选`、`提案`和已写入分册的卡面必须分开标注；没有测试证据不写“已完成”“已验证”“已平衡”。

## 共同校对

1. 术语与[功法树总览](./CULTIVATION_TREES.md)、[战斗规则](./COMBAT_RULES.md)、三份分册和[事件规则](./rules/EVENT_RULES.md)一致。
2. 逐门核对普攻、怒技、行旅和四层选择是否互相支持；逐事件核对即时得失、非致命败北线和后续回响是否明示。
3. 使用“新增、消耗、保留、替换、触发、结束”描述实际行为；概率写概率，次数写次数，持续写时长，具体数值待测时不要造假精确。
4. 卡面目标是易扫读，不为凑字数删掉条件、代价或情绪；段落长短服从信息完整和玩家能复述。
5. 提交前确认：玩家能否不看开发页复述主要变化？直接强化是否直接写出对象？机制改写是否写清输入、顺序、次数和失效？
