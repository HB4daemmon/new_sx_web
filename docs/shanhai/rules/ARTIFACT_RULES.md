# 法宝统一规则与结算边界

> 状态：一期可开发、可评审的共同规则；不是数值平衡结论。
> 本页约束 [ARTIFACTS.md](../ARTIFACTS.md)、[ARTIFACTS_COMMON.md](../content/ARTIFACTS_COMMON.md)
> 与 [ARTIFACTS_MYTHIC.md](../content/ARTIFACTS_MYTHIC.md) 的触发、强化、唯一性和敌方装备。
> 具体伤害、治疗、护盾、概率、状态时长和倍率仍须首测；本页固定顺序、次数和资源边界。

## 1. 适用范围与唯一性

- 一局只有一门当前主修；法宝只修改已有普攻、怒技、行旅、属性或公开状态，不提供第二门主修、第二个完整主动作或隐藏状态。
- `FB01-FB08` 与 `FB41-FB48` 是本局唯一实体；同一实体不能被复制、重复掉落或因读档再发。`FB09-FB40` 是公共器物，同一 `item_id` 对每个持有者最多一件生效，玩家和敌人可以各自持有同 ID。
- 公共器物的持有者唯一不等于原典实体唯一。公共法宝由投放册库存和固定事件控制；已持有候选在确认前改为同器强化或公开回退，不生成第二件。
- `R01 -> FB41`、`R02 -> FB42`、`R03 -> FB43`、`R04 -> FB44`、`R05 -> FB45`、`R06 -> FB46`、`R07 -> FB47`、`R08 -> FB48` 是固定映射。对应 `R` 已发出、已完成或已经转移的事件从本局机会池排除。
- 读档回到已经完成的事件页只读取事件完成账、奖励确认账和实体转移账，不重新抽牌、不再次领奖、不恢复已消耗的唯一实体。
- 敌人的法宝与玩家共用同一 ID 效果，但敌人没有玩家行旅收益。战前公开敌方完整构筑、实际装备、先手、关键压力、胜利奖励和失败边界；敌情不是 `FB41` 的付费或独占技能。
- 一般战斗胜利不等于获得敌人全套装备。只有奖励字段或对应 `R` 事件明示转移时，才把一个指定法宝写入玩家构筑。

## 2. 事件模型

### 根动作、基础段与派生事件

1. 每个角色每轮至多一个 `root_action_id`，即一次普攻或怒技主动作。速度只决定本轮先后，不能由法宝或追击增加根动作。
2. 根动作内每个功法卡面声明的伤害段都有独立 `base_segment_id`，仍属于同一个 `root_action_id`。二段、三段和四段基础攻击按卡面逐段结算。
3. 法宝追加伤害、追剑、反伤、额外 DOT 和治疗/状态派生输出使用 `derived_event_id`，必须带父动作或父持续事件的 `source_chain_id`。派生事件不是新的根动作，也不自动重跑父事件触发器。
4. **附加伤害**是当前根动作内的额外伤害，例如 `FB45` 的两段追加；**派生伤害**是由持续伤害、反伤或其它结果产生的后续伤害。两者都不能增加主动作数。
5. 额外 DOT 可以被明确读取“实际持续伤害”的其它能力读取一次，但不再次施火/施毒、不重新创建同类 DOT、不消费原状态的层数或时长、不递归回到自己的触发器。
6. 同一份怒气、护盾、治疗、毒层、燃烧、虚弱、破甲或剑势只能消费一次。不同能力可以读取已登记的结果，但不得重复扣除或把同一结果复制成新的根资源。
7. 每条派生分支保留祖先触发路径，同一能力不能沿自己的输出回到自身，形成重入。去重键同时包含持有者、能力、触发类型及卡面粒度对应的动作/基础段/治疗事件 ID；并列基础段和独立治疗事件不是同一触发。KF07 明示的每基础段连雷、KF09 明示的逐段附火、每次治疗的 FB15 修正，都不能被“同根动作运行过该能力”错误拦截。每回合、每战次数再由独立计数器约束。

### 实际伤害与护盾吸收

- **基础直接伤害：**功法普攻或怒技卡面声明的根动作伤害段。`FB14`、`FB23`、`FB25`、`FB41`、`FB44` 等基础伤害修正先对当前根动作锁定一次预算，同一根动作的多段不重复乘算。
- **命中：**直接攻击段未被特殊闪避即视为命中；命中可以被护盾完全吸收，命中附效仍按卡面判断。
- **护盾吸收：**伤害经过攻击、防御、虚弱、破甲等修正后，先由目标护盾承受的部分，记为 `shield_absorbed`。
- **实际伤害：**该次伤害最终扣除目标气血的部分，记为 `actual_damage`；它不包含护盾吸收。只有 `actual_damage > 0` 才满足“造成实际伤害”。
- 直接伤害、附加伤害和持续伤害都要先完成伤害结算，再由依赖 `shield_absorbed` 或 `actual_damage` 的法宝读取记录。

### 治疗、来源链与战外

- 每次治疗先建立唯一 `treatment_event_id`，再按治疗前缺口拆为**有效治疗**与**真实溢出**；同一份治疗量不能同时计入两边。
- `FB15` 对所有自身治疗事件各修正一次，包含功法根治疗、行旅允许的治疗和法宝派生治疗；同一 `treatment_event_id` 不会重复读 `FB15`。同一动作内的两份独立治疗各自可以增量，不能将整条来源链误作只有一次治疗。
- `FB17` 读取每个合法自身治疗事件的有效部分；`FB35` 读取真实溢出，并受每回合一次的全局计数限制。二者可以从同一根治疗各自产生一次不同输出。
- `FB36`、`FB43`、`FB32` 等法宝治疗也可进入治疗管线，继续被其它不同能力合法读取；它们不会重新开启怒技完成队列、不会回到已结算的根治疗，也不会让同一能力在同一来源链重入。
- 战外治疗只结算允许的气血恢复和增量。战外不得凭空生成战斗护盾、毒、燃烧、怒气或额外主动作；因此战外的 `FB17` 不造盾，`FB35` 不施毒。

## 3. 速度、回合与根动作顺序

### 速度轮初固定

1. 每轮开始，在双方存活且战斗继续时，按当前速度和战前固定同速顺序建立 `round_order_id`。该顺序覆盖本轮双方主动作，不在行动开始重新锁定或重掷速度。
2. 轮内发生的速度变化从下一轮排序生效；`FB27` 只改变速度属性，不增加动作数、攻击频率、积怒、治疗、施毒或造盾次数。
3. 轮内按 `round_order_id` 轮流取每方一个根动作。角色死亡或非致命败北后立即停机，未行动方不补回合。

### 一个根动作

1. 根动作开始时锁定当前怒技门槛、目标动作前状态和功法声明的基础段序列；`FB41` 的怒技增伤只读取此时已有的旧破甲。
2. 若为怒技，先按已有功法/天赋和法宝计算本次实际门槛与支付，再支付怒气；支付后不因闪避、失败或目标死亡退款。若支付会超过怒气上限，按本页 `FB44` 规则截断，不能透支。
3. 逐个基础段处理特殊闪避、直接伤害、护盾吸收和实际伤害。被闪避的段不发该段伤害和命中附效；普攻动作仍完成并获得基础怒气。
4. 基础段命中后按卡面顺序处理首段施毒、施火、破甲、虚弱等附效，再处理同一根动作的法宝追加段。追加段带父 ID，不触发同类首段效果或新的根动作。
5. 根动作自身原有的治疗、护盾、状态、追击和基础怒气登记完成后，才进入完成队列。持有者死亡或非致命败北时不进入完成队列。

### 角色死停

- 任一角色在伤害或事件结算处死亡，或达到非致命败北线，战斗立即结束。尚未结算的基础段、追加段、反伤、持续伤害、治疗、护盾、回怒、状态和完成后效果全部取消。
- 死亡来源者不能在死后触发“动作完成”或“持续伤害后”；死亡目标不再承受同一根动作的后续段。不得用后置法宝效果复活、补行动或补发奖励。
- 节点奖励、行旅效果和法宝取得只在玩家活着完成其真实节点、战斗或事件确认后结算；战斗内死亡不会延迟生成奖励。

## 4. 完成队列与治疗去重

完成队列不冻结一份会被重复消费的根治疗。根动作只登记一次治疗事件，队列按以下顺序消费并记录：

1. **状态清理：**处理 `FB30` 等明确的自身状态移除；移除不生成攻击、治疗、护盾或怒气。
2. **根治疗：**逐个消费本根动作已经登记但尚未落地的 `treatment_event_id`，先经 `FB15`，再拆有效/真实溢出，并让 `FB17`/`FB35` 读取各自结果。已经落地的根治疗不在后续步骤重播。
3. **完成快照：**根治疗落地后记录一次当前气血、最大气血、护盾、状态和本战计数快照。`FB43` 以此快照判断缺血治疗或满血护盾，不能在同一队列内因自身输出改选第二项。
4. **完成后治疗：**按快照和次数处理 `FB43`、`FB32` 及其它明确的完成后治疗。每个新治疗建立新的 `treatment_event_id`，经过一次 `FB15`；其有效/溢出可被合法的不同能力读取，但不重开本队列。
5. **护盾：**处理 `FB17` 的有效治疗护盾，再处理 `FB43`、`FB38` 和其它完成后护盾。每个独立 `shield_gain_event_id` 只经 `FB31` 一次并检查公共上限。
6. **回怒与层数：**处理 `FB34`、`FB39`、`FB46` 等回怒，再处理 `FB26` 的攻击层。回怒只供后续主动作；层数在下一根动作前生效。

由法宝治疗产生的护盾、毒或回怒若属于战外事件则禁止；若属于战斗内合法来源链，则仍按各自每回合/每战次数和 `ability_id` 去重。完成队列结束后不重新触发根动作。

## 6. 概率、闪避与多段

- 普通攻击默认命中；特殊闪避只来自明确卡面，例如 `FB33`。`FB33` 在本战首个合资格直接攻击段上做一次概率检定，失败是一次真实失败，不保证成功、不重掷、不改变为“没有资格”。
- 特殊闪避只处理一个直接攻击段，不能躲避燃烧、中毒、反伤或事件扣血。被闪避段不发伤害和命中附效；攻击者的普攻动作仍完成并积基础怒气，已支付的怒技怒气不返还。
- 多段基础段各自保留命中和附效资格；同一能力写“首个基础命中”时只取第一段实际命中，后续基础段和追加段不重复。
- `FB45` 的两段追加、`FB48` 的额外燃烧结算、追剑和反伤均为当前根动作的派生事件。它们不重新触发同类首段效果、概率检定或主动作。
- `FB39` 只读取本回合自身第一次真实概率失败，包括自身 `FB33` 的合资格闪避失败；对手的检定不属于自身输入。没有资格、特殊闪避成功、确定性未命中和派生段不算失败。`FB24`、功法概率和 `FB39` 各按自己的 `ability_id` 去重。

## 7. 持续伤害、反伤与治疗链

### 反伤

1. `FB11` 读取一个敌方主动作内是否发生护盾实际吸收，同一敌方主动作至多反伤一次；反伤是原动作派生伤害，不产生反伤者的新主动作。
2. 反伤若造成目标 `actual_damage > 0`，`FB34` 可在本回合第一次合资格反伤后回怒；反伤本身不再触发 `FB11` 或其它同类反伤。
3. 反伤命中敌盾只算命中，不算实际伤害；没有气血损失就不触发依赖实际伤害的回怒、施弱或治疗。

### 燃烧、中毒与额外 DOT

1. 每个燃烧或中毒实例在其合法持续时点只结算一次；被卡面提前消费的旧实例不再产生消费后的 tick。
2. `FB20`/`FB21` 只修正持有者自己的持续实例，不把 tick 改写成新的状态或概率检定。`FB36`/`FB37` 在护盾吸收和实际伤害登记后各自读取本回合第一次合资格事件。
3. `FB47` 读取自身施加的燃烧实际伤害；`FB48` 的额外 DOT 也沿父动作记录，若满足其它能力的明确实际伤害输入，可被不同能力读取一次，但不能再次触发 `FB48`、重复消费燃烧或递归施火。
4. 新施加的燃烧、中毒、虚弱和破甲属于新状态实例；同一动作内不把新层提前当成旧 tick，也不让新层参与动作开始时已经完成的旧状态检查。

### KF09 旧火/新火时序

- 采用 `KF09-J4-B` 时，怒技开始先锁定动作开始前已经存在的全部己方燃烧，并只消费这份旧火一次、结算其爆发；这一步不会消费本次怒技新产生的燃烧。
- 旧火消费完成后，按功法基础段逐段结算直接火伤和新施火。新火保留正常层数与时长，不能在同一怒技再次被 `J4-B` 消费。
- 若持有 `FB48`，首个实际基础命中施加新火；动作末额外结算目标当时仍存在的己方燃烧，通常包括本动作新火，不减少新火层数或时长。若角色或目标已死停，则不执行动作末结算。

## 8. 名器与公共器物取得

- `FB41-FB48` 只能由对应 `R01-R08` 转移同一实体。守器者的实际装备不等于玩家奖励；普通敌人、商店、`E06` 和普通/精英随机掉落不得复制名器。
- `R04 -> FB44` 支持两种互斥的合法取得条件：确认页明示的“珍稀旧器加灵石永久交换”，或守器者战斗胜利并完成明示转移条件。任一条件完成即转移同一 `FB44`，不再追加一次确认或隐藏检定。
- `FB09-FB40` 的公共同名器可由玩家和敌方各自持有；同一持有者仍只有一件生效件。敌方装备字段与胜利奖励字段分开，装备存在不自动掉落。
- 取得、强化、临借和停用必须在事件确认页或战前明示。换功法不会自动卸载 `FB10`、`FB16`、`FB27`；只有移除、抵押、牺牲或明确停用才失效。

## 9. 行旅节点、FB40 与战外边界

1. 进入真实节点时记录 `node_id`、当前主修和当时生效的行旅法宝版本；节点内多场战斗仍只在整节点活着完成时结算一次。
2. 本节点新取得或强化的行旅法宝从下一节点生效；退出、死亡、跳过、重复打开和读档回到完成页不重发收益。
3. `FB40` 每幕开始时将 `act_claimed=false`。只有持有且生效时活着完成一个真实战斗节点才将其设为 `true` 并回血；取得前已经完成的首个战斗节点不追溯，但不把本幕计数提前置为已领，取得后下一合资格节点仍可触发。
4. `FB40` 暂时停用、临借归还或事件内不生效时不触发，也不追补停用期间节点；本幕已经由 `FB40` 结算后不因换法、读档或重复节点刷新。
5. `FB28`、`FB29`、`FB40` 和功法行旅收益不对敌人结算。战外的 `FB15` 治疗修正不制造 `FB17` 护盾、`FB35` 中毒或其它战斗资源。

## 10. 同层效果、强化与验收

- 同一事件同时有功法天赋和法宝时，先按既有功法卡面及其专门顺序锁定、消费和结算；法宝只追加本卡声明的输入/输出，不替换同层旧效果，不把旧效果再消费一次。
- 强化最多两次，仍是原 ID、原实体和原主要变化；只能提高幅度，不能新增主动作、第二条行动链或隐藏状态。满强化时在确认前展示公开修为或既定回退。
- 验收必须能区分 `root_action_id`、`base_segment_id`、`derived_event_id`、`source_chain_id`、`shield_absorbed`、`actual_damage` 和 `treatment_event_id`。
- 逐场检查：每轮先按轮初速度行动；死亡立即停机；特殊闪避只处理一个直接段；怒技先付后结算；返怒不重开当前动作；额外 DOT 不递归、不多耗。
- 逐项检查：`FB11` 每敌方主动作一次；`FB32` 每战前两次怒技；`FB34-FB37`、`FB39` 每回合一次；`FB33` 概率机会非保证；`FB40` 取得后的本幕首个有效战斗节点可触发。
- 逐项检查：普通 `FB09-FB32` 第一幕起，珍稀 `FB33-FB40` 第二幕起；八件名器固定 `R01-R08`；已持有/已发/已完成来源不重抽；普通公共同 ID 不误写成全局唯一原器。
