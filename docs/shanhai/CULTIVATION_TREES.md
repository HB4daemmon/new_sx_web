## 1. 设计范围

1. 本轮先搭十套具备完整成长方向的功法树；每门功法同时服务斗法与行旅。
2. 功法可以通过事件取得或替换，事件不是强制获得某一固定功法。
3. 功法分普通、珍稀、传奇三档；档位描述取得难度与基础强度，不代表普通功法的分支更少或成长上限必然更低。
4. 功法是一门当前主修，树内天赋属于该功法；不采用旧式“主功法加若干辅功法”叠加。
5. 角色个人自动战斗，不提供手动放技能、不组建编队；通关后可保存个人构筑供后续自动大战。
6. 本轮不预设玩家对战；所有“强弱”先按单人斗法、行旅收益和自动决策可读性评估。
7. 神话意象只作原创机制转译；本文不陈述任何古籍史实，也不要求玩家了解原典。
8. 本轮采用五普通、三珍稀、二传奇，共十套完整树；这不是“开局十选一”。普通五门可作为起始候选，其余通过局内事件获得。
9. 一门主修、五个境界及四次进阶是本轮结构提案；用户已明确的是功法可替换、各有境界树、传奇基础较强、法宝不限数量，不把其余提案写成已批准数值。

### 2.1 表格使用方式

1. 表中“核心”是评审用的机制边界，不是尚未写出的具体数值。
2. 每门功法在炼气获得基础动作，在筑基、金丹、元婴、化神四境各提供同层 A/B/C 选择；炼气不额外选天赋。
3. 同一境界只选 A、B、C 之一；已选结果保留在该功法树中，不能靠普通战斗反复重洗。
4. 表中“成长与转型观察点”代表每境可继续强化或改变玩法的方向，不代表预先承诺某条分支一定更强。
5. 三份分册合计 120 个候选节点，提供 30 条四层示例路线；路线不是硬前置，也不宣称全部组合已经运行或通过数值测试。

## 3. 共同战斗规则

### 3.1 功法与境界

1. 暂以炼气开局；境界顺序为炼气、筑基、金丹、元婴、化神。
2. 五境是成长层级，不必一一对应五幕剧情；化神后的最终质变必须经历数场实战才能评估。
3. 每门功法一共四次境界选择：筑基、金丹、元婴、化神各一次。
4. 炼气提供基础功法和起步输入，不额外制造“隐藏第零次天赋选择”。
5. 每次选择从当前层的 A/B/C 节点中选一项；选择后保留，直到发生受规则约束的分支整备。
6. 不设置额外天赋装备上限；境界选择本身就是该功法的成长承载方式。
7. 树为分层分岔并允许交叉；固定主树可见、可规划，不强制全随机三选一。
8. 同层节点必须以基础功法或本节点实际提供的输入为前提，不能因未选上层某条路线而出现无意义死选。
9. “转型”是改变资源用途、触发方式或战斗侧重点的分支，不自动意味着更高面板。

### 3.2 自动战斗与怒气

1. 角色只有一个主动作决策：默认足够怒气时施放怒技，否则执行普攻。
2. 怒气是唯一通用战斗释放资源，不额外引入第二套能量条。
3. 普攻完成后获得基础怒气；即使普攻未命中，也完成该动作并提供基础怒气，确保开局零怒可以运转。
4. 返怒效果用于下一次主行动；“连击”是一次动作内的派生段，不是完整额外轮。
5. 派生段不能绕过主动作节奏制造无限递归；任何来源追踪都必须标出首次触发与再入边界。
6. 自动决策优先遵守功法的固定规则和当前状态，不要求玩家在战斗中手动选目标或插入技能。
7. 个人构筑保存的是主修、已选节点、永久属性和法宝状态；临时战斗状态不应作为永久战斗起点。
8. 本轮以单目标斗法搭树，不引入邻近目标、群体选取或站位。怒技先支付所需怒气，再结算动作；除明文蓄怒规则外，不默认清空全部怒气。
9. 自动优先级为：兑现明确的一次强制普攻，再检查当前功法的释放门槛，最后选择怒技或普攻；强制普攻不能获得额外行动。单门特例必须在分册写明。

### 3.3 属性与状态语义

1. 本轮暂用属性词表：攻击、防御、最大气血、暴击率。
2. 特定效果的触发概率是该效果自身概率，不等同于全局暴击率；其他属性词待后续扩展。
3. Buff 在战斗结束时清除，不允许以战斗外累计的临时层数无限滚入下一场。
4. 负面状态不得无限硬控；必须有持续、清除、抵抗或兑现边界。
5. 同一效果若同时改变数值与触发窗口，应明确记录先后顺序，避免“先转化后再重复吃原效果”。
6. 每个节点需说明它提供的是基础输入、额外触发、转换规则还是唯一改写，不能只写“更强”。

### 3.4 治疗、护盾、火与毒

1. 治疗区分有效治疗与溢出治疗，同一份量不能同时归入两者。不同追加效果可以观察同一次真实治疗并各自产生收益；消费或替代效果只能使用其实际分配到的那一份量，不得重复全额花费。
2. 护盾至少区分获得、被敌人消耗、由角色主动消耗、自然到期四种事件；节点引用时必须写清事件类型。
3. 燃烧是短周期状态；叠加的是强度或明确的新实例，不能自动无限刷新当前实例的到期时间。
4. 毒是较长周期状态，可累层但必须有层数预算、清除边界和兑现上限待测。
5. 火与毒的持续状态都不能借由“每次触发再延长”形成无界持续；详细分册要给出实例或层数的生命周期。
6. 盾、治疗、燃烧、毒的转换只能消费其明确输入，不得暗中借用未选择的上层节点。
7. 治疗增益在发起该次治疗前读取，生机等“治疗后生层”只能影响下一次治疗；本次追加治疗不能递归触发自己的治疗增幅。
8. 到期追加尾伤不等于新建持续状态；除节点明确提供新实例外，不允许尾伤再次发出同一“到期”并无限续期。

## 4. 稀有度与强度关系

1. 传奇功法在同投入、无专门配合时通常应有更强基础表现；这是档位预期，不是已完成的数值结论。
2. 传奇是正向机缘，不强加暗伤或诅咒来抵消取得奖励；它可以有自然的启动、节奏与属性适配差异。
3. 普通功法不统一设置更高成长率来保送超越；其竞争力来自专精强项、属性转化、叠层管理和高频协同。
4. 在合适的环境、敌人分布、法宝组合和已选节点下，普通功法可以超过传奇功法的实际伤害或通关效率。
5. 共用境界上限和选择次数，只说明比较口径一致，不代表各门功法收益相同。
6. 在数值未测前，不声称“普通必胜传奇”“传奇绝对最优”或任何固定排名。
7. 评审至少分别看单场爆发、连续战斗续航、行旅损耗、自动决策稳定性和对法宝的依赖。
8. 对照测试采用相同境界、属性预算和法宝总价值，分别测试适配与不适配配置。要验证的是普通功法有值得专精的强项，而非拿完整普通构筑对比裸传奇。

普通功法反超的候选依据：金刚功以最大气血与盾损产生反击，养剑诀以保留剑势与多段命中反复兑现法宝，回春功把治疗与溢出变为持续输出。三者都应在其擅长的配置和战斗长度下有竞争力，但没有一个已被证明数值优于传奇。

## 5. 进阶、换法与分支整备

### 5.1 事件取得与常规换法

1. 事件得到新功法时，玩家可在事件当场选择换法，或保留法本待之后使用。
2. 常规换法只发生在有限修整机会；不能把事件选择伪装成随时免费洗点。
3. 换法后仅当前主修功法及其树有效，包括该功法绑定的行旅能力；旧树全部卸下，不叠加。
4. 角色保留境界、修为、属性和法宝；首次启用新功法时，按当前已达境界补选该功法应有的相同次数。
5. 再次启用旧功法时恢复旧树已选项；切回不是免费洗点，也不重置已经获得的成长。
6. 改变同一功法的分支是单独的、有限的整备机会，不能借换法规则无限重选。
7. 本轮不另加功法熟练等级；功法成长只通过境界节点、允许的分支整备和明确的永久收益表达。

### 5.2 换法时的状态处理

1. 换法不回满血、不重触发入门赠品、不重置已领成长。
2. 永久修为保留；临时战斗状态不保存、不带入新功法。
3. 原功法未结算的行旅进度随原法冻结，例如日照周期或节点计数，不能切法刷满；这不包括战斗中的增益层数。
4. 切回原功法时只能恢复其合法的持久进度；已经过期的战斗状态不得复活。
5. 新功法的初始状态须按规则生成，不得继承旧法的怒气、护盾、燃烧、毒层、临时 Buff。

### 5.3 行旅绑定

1. 行旅能力在节点开始时绑定当前功法；节点完成时统一结算一次。
2. 节点末取得的新功法不追领该节点的行旅效果；下一节点开始后才可生效。
3. 行旅收益必须有真实用途，例如影响资源、损耗、选择质量或后续战斗准备，不得只作为故事判定。
4. 行旅结算不得绕过斗法状态生命周期，也不能把战斗临时 Buff 伪装成永久属性。
5. 气血代价修正先在节点最终结算中应用，再扣除代价并判定生存；明确写“支付后返还”的能力只能在玩家存活时返还，不能复活。随后领取完成收益，死亡不能靠节点末回血救回。
6. 同一节点 ID 的同一收益只领一次；战斗拖长不增加节点数。演练、通关后的自动大战和反复打开结算页均不生成行旅修为或物资。
7. 下一战准备归属原功法，切换后暂不生效且不得叠存多份；只有仍主修该功法时才会在下一场战斗兑现并清除。它不进入通关封存。

## 6. 法宝边界

1. 法宝不区分“斗法法宝”和“行旅法宝”；同一件法宝可在两种场景按其明确条件生效。
2. 持有件数和同时生效件数不设统一上限；不得暗中新增槽位、负重或“仅前 N 件有效”的限制。
3. 有限节点可以限制法宝产出、选择机会或取得来源，但这不是装备容量上限。
4. 仅明确标注为互斥或唯一的效果需要替换；唯一组必须写出组名和替换对象。
5. 追加效果和转换效果必须分开写清：追加是不删除原效果，转换是将指定输入改写为新效果。
6. 同一法宝的同一唯一效果不能通过多件法宝无限叠加；非唯一效果是否叠加必须写明规则。
7. 来源追踪允许跨多件法宝多跳，但同能力同源不允许无限再入；触发链必须有终止条件。
8. 法宝不得改变功法只有一门当前主修的边界，也不得偷偷提供第二棵独立功法树。
9. 法宝可成为普通功法在特定构筑下超过传奇功法的协同来源，但不得因此改写稀有度基础关系。
10. 唯一组只用于确实不能同时成立的行为改写，不得把所有护盾或治疗标签归为同一组，变相取消不限量与混搭。
11. 追加效果依固定规则顺序生效，不以拾取先后抢占资源；替代效果装配时必须明确归属，运行时记录剩余消费预算。性能与连锁深度是实现测试问题，不等于只让前几件法宝有效。

## 7. 验收矩阵

| 命名与 ID | 十门名称、ID、稀有度与总览一致 | 逐项核对 KF01-KF10 |

| 唯一效果 | 只有明确唯一/互斥组才替换，追加与转换可读 | 效果来源图 |
| 来源追踪 | 可跨件多跳，但同能力同源有再入终止条件 | 触发链追踪 |
| 换法公平 | 不回血、不重赠品、不刷累积；切回恢复原树选项 | 多次换法回放 |
| 行旅绑定 | 开始绑定、完成结算，节点末新法不追领 | 节点边界日志 |
| 永久与临时 | 永久修为保留，临时战斗状态不存 | 存档/读档对照 |
| 真实用途 | 行旅收益影响真实资源、损耗、选择或战斗准备 | 行旅收益链路 |
| 数值声明 | 当前只做机制草案，不声称已平衡 | 设计评审记录 |

## 8. 当前未决事项

1. 各境节点的具体数值、持续回合、层数预算、清除条件和兑现上限待统一测试。
2. 各门怒技的具体门槛与普攻积怒量待测；单主修只按其明确形态选择怒技，不再新增任意多怒技槽位。
3. 法宝非唯一效果的默认叠加规则需要在法宝目录中逐件声明，不能由本总览推断。
4. 普通功法对传奇功法的条件超越，需要用固定敌群、行旅长度和法宝样本做对照，不在本文预先结论。
5. 本轮完成结构与文字走读；实现时还需验证所有跨层组合、法宝交互和自动行为，不能把 120 个条目计数当成平衡验收。
6. 本文不代替各分册的节点设计；若分册出现与本文冲突的隐式槽位、额外资源或免费洗点，应退回修正。

## 9. 分册交付接口

1. 每门功法的分册条目必须先写基础功法，再按炼气、筑基、金丹、元婴、化神排列。
2. 每个进阶境必须明确 A/B/C 三个可选节点，以及每个节点的名称、输入、效果和转型意图。
3. 节点输入必须来自基础功法、已选节点或本节点先行提供的效果；不得引用不可达的隐含前置。
4. 节点效果需分列斗法效果和行旅效果；两者共用同一资源时要说明结算先后。
5. 每个触发型效果应标明触发事件、触发概率或条件、消费的资源及是否允许再次触发。
6. 每个持续型效果应标明持续周期、叠加方式、清除方式、到期行为和战斗结束处理。
7. 每个转化节点应列出原输入、转化后输出、是否保留原输入，以及不能重复转化的边界。
8. 每个唯一或互斥效果应标出唯一组名称、被替换对象和替换后是否仍可获得追加效果。
9. 节点若引用法宝，应说明是追加、转换、放大还是触发法宝效果，不得改变法宝件数边界。
10. 节点若引用来源追踪，应列出允许跨件跳转的链路和同源再入终点。
11. 每门功法都应至少有一条稳定基础路线、一条资源或状态专精路线和一条明显转型路线。
12. 稳定路线不应依赖高稀有法宝才能启动；专精路线可以依赖构筑，但依赖项必须可见。
13. 行旅节点应说明收益何时获得、能影响何种真实资源，以及换法或节点结束时如何处理。
14. 分册不得重新定义“当前主修”“主动作”“怒气”“临时状态”等总规则词。
15. 分册完成后先做机械核对，再做至少一轮人工构筑走读，最后才进入数值测试。
16. 机械核对关注命名、境界次数、前置可达性、唯一组、状态清除和相对链接。
17. 构筑走读至少覆盖零怒开局、连续普攻、怒技循环、换法切回和节点末换法五种路径。
18. 数值测试应分别记录单场伤害、连续节点损耗、恢复量、状态兑现量和法宝协同贡献。
19. 若某节点需要临时例外，例外必须写在节点本身并注明覆盖的共同规则，不得只藏在实现约定。
20. 后续发现冲突必须同时修正文档两处，不能要求开发者自行猜测哪处优先。本轮以十门主修功法树和不限件数法宝替代旧构筑方案，不更改游戏代码或旧事件奖励数据。
