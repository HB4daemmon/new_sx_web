# 敌人强度与配装基线

> 日期：2026-09-21。
> 状态：首轮 target 设计；非实测；`measured=null`。
> 本页是敌方配置、训练盘和真实遭遇的验收合同，不是已实现的胜率、TTK 或伤害平衡结论。
> 公共怒气、卡面效果、法宝层数和事件节点分别引用 [METHODS.md](./METHODS.md)、
> [ARTIFACT_SYSTEM.md](./ARTIFACT_SYSTEM.md)、[BALANCE_BASELINE.md](./BALANCE_BASELINE.md)
> 与 [RUN_STRUCTURE.md](./RUN_STRUCTURE.md)；事件与幕结构链接
> [EVENT_BASELINE.md](./EVENT_BASELINE.md)、[ACT_BASELINE.md](./ACT_BASELINE.md)。

## 1. 地位与测量边界

本页只定义敌方遭遇的难度分档、固定配置、压力机制、训练方法和首测目标。
敌方难度分档不等于功法或法宝稀有度：普通敌人可以使用稀有功法，终战也不强制传奇；
难度来自生命、承伤、行动压力、机制数量、阶段读法和资源节奏的组合。
功法位阶仍遵守普通基线、稀有高 10%、传奇高 25% 的预算；法宝沿用各自位阶预算。
这些是同条件下的能力目标，不能拿来自动推导敌人档位、胜率或掉落。

`P` 只用于十五回合木桩的预算诊断，不能替代真实遭遇胜率、TTK、死亡率或通关率。
木桩得到的 `D/L/H/P` 不得被写成“玩家一定赢”或“敌人一定在某回合死亡”。
真实遭遇必须另跑固定敌人、固定种子和实际战斗逻辑，并单独记录 `win_rate`、`TTK`
及 `early_end`；本轮新规则尚无运行时对抗实测，不能拿旧版模拟或估计数字填充。

首轮所有示例都是原创匿名敌人身份；若未来映射神话人物，字段保留
`myth_source_ref:null`，不在本页编造原典出处。敌人装备与掉落是两个系统：
敌方使用合法卡面和层数不表示该件装备会掉落，也不从敌方配置复制玩家节点奖励。

## 2. 难度分档

| 档位 | 目标战斗长度 | 主压力 | 辅压力 | 目标损耗带（参考盘幸存胜利样本中位数） |
| --- | --- | --- | --- | --- |
| 普通 | 3-5 轮 | 1 项 | 0 项 | 起始最大 HP 的 3%-6% |
| 精英 | 5-8 轮 | 1 项 | 1 项 | 起始最大 HP 的 8%-14% |
| 幕首领 | 8-12 轮 | 最多 2 项互动机制 | 最多 1 次可读转折 | 起始最大 HP 的 12%-20% |
| 终战 | 10-15 轮 | 最多 2 项 | 最多 1 项 | 起始最大 HP 的 18%-30% |

上表的目标是参考盘中“幸存且胜利”样本的中位数目标带，不是每个构筑的自动扣血值，
也不是所有玩家 build 都必须保证的胜利线。死亡、未决和错误样本仍全部进入分布报告；
不能只挑成功样本来宣称敌人平衡。

`W=15` 是统一基线观察上限，不是游戏超时败北规则。超过 15 轮仍未结束的样本记为
`over_window` 或 `undecided`，保留实际轮数和事件账；不得暗定第 16 轮自动判玩家败北。
如果真实产品日后需要超时规则，必须另在运行时和 [ACT_BASELINE.md](./ACT_BASELINE.md)
写明，不能从本页的观察窗推导。

单轮爆发预警线如下，均为复核信号而非实装硬上限：

| 档位 | 单轮净 HP 损耗预警线 |
| --- | ---: |
| 普通 | 12% `H_ref` |
| 精英 | 22% `H_ref` |
| 幕首领 | 30% `H_ref` |
| 终战 | 35% `H_ref` |

`H_ref` 是参考盘起始最大气血的原始值，不是功法评分中归一化的 `H` 指数。
超过预警线要回查触发来源、入场带伤、最低血线、阶段转折和种子，不自动削平伤害。
低血可以死亡；报告不得伪造一次“战外恢复”或把未发生的满血治疗补进战斗。

## 3. 离线校准与公共参照

每一幕按前段、中段、后段和首领/终战入口切分为离线 segment；先冻结该 segment 的
参考 loadout、敌方配置、种子集合和动作规则，再开始比较。冻结后不得因某个玩家 build
表现不佳就临时提高敌人生命、免疫或怒气。

同一境界、同一基准版本的一批 segment 和 seed 共享唯一的 `D0/L0/H0`。不能按功法、敌人档位或单件法宝
各自重建参照再归一化；否则会把真实难度差异洗掉。不同压力族可以有独立原始事件账，
但仍要指向同一批公共主参照。

离线校准只锁定输入和记录口径，不把目标值写成卡面常数。目标样本若没有幸存胜利，
该档位中位数写 `null` 并说明 `reason=no_reference_survivor_victory`，不以零补齐。
分布至少报告 `death_rate`、`undecided_rate`、`error_rate`、`p10/p25/p50/p75/p90`、
每轮峰值净损耗、战前带伤和全战最低血线。

真实敌人 stage 配置在战前完整公开并固定：功法、已达到的天赋、法宝及层数、基础属性、
阶段来源、动作优先级、奖励类型和胜败边界都可查。敌人不读取玩家当前 build 来动态变强，
不偷看玩家尚未取得的战后奖励，也不把未领取的传奇候选当作敌方隐藏输入。

## 4. 生命损耗与公共时序

战斗净耗定义为：

```text
net_hp_loss = 入场当前 HP - 战末当前 HP
```

`net_hp_loss` 可以为负，不能 clamp 到零。台账另外分列：
`external_damage`（敌方实际入血）、`self_damage`（自伤实际入血）和
`effective_self_heal`（真正填回气血的战斗内治疗）。护盾吸收不再从净耗中扣一次，
战外恢复也不进入本战有效治疗。

原始 `H_ref` 只读参考盘入场时的起始最大气血，归一化 `H` 仍按功法基线计算。战中变身、临时最大气血、上限变化和因上限变化导致
的当前血量截断另记 `dynamic_max_hp`、发生轮次和 `hp_cap_adjustment`，不能用战末最大
气血冒充固定 `H`。若动态上限使入口/出口差额与损伤台账不相等，保留差额原因，不篡改
外来损伤、自伤或有效治疗。

公共怒气仍按共享合同结算：入战基础 `+50`，每次完成普攻主动作 `+25`，每个有效敌方
主动直接攻击段 `+5`，完整存活轮轮尾 `+10`。多段攻击逐段给受击者回怒；速度只决定
先后，不增加主动作、普攻、毒火、治疗或护盾次数。开场削怒护栏为 `50`，轮内每目标
外来削怒护栏为 `20`；削怒在轮尾统一结算，不取消本轮已锁动作或已支付怒技。

战斗顺序固定为：轮初锁双方动作和支付值；逐段执行并记账；死亡立即停止后续段、治疗、
派生和未结算收入；轮尾先处理 DOT、派生与死亡，再合并怒气、上限和削怒；窗口结束记
未兑现状态。敌我使用同一段边界，不能让敌方多段只造成伤害却不给玩家相应受击回怒。

## 5. 敌方合法配置

敌人可以使用同定义的功法、天赋和法宝，但必须满足当前配置的境界和层数。`n` 是已达到
的天赋层数上限；`n=1` 只能选 J1，`n=2` 才能选 J1/J2，不能跨阶选尚未达到的天赋。
缺少现有主修、天赋、法宝或公开 stage rule 来源的阶段能力，写入 `phase_source:null`
和 `target.status="待设计"`，不静默生成敌人隐藏技能。

同名普通法宝按卡面上限叠层，稀有/传奇默认单件；同一局中的唯一实体只能有一个
持有者。非唯一普通法宝可由敌我分别持有，但不会因为敌方持有就复制一份玩家奖励。
所有属性系数和未实现阶段数值在首轮保持 `null`，不能把示例层数叫“已平衡”。

### 5.1 四套精确合法示例

以下四套只用于校准和验收，身份匿名原创，`myth_source_ref:null`。每套的 `stats` 中
未定系数仍为 `null`；其合法性只表示 ID、层数、输入和境界关系正确，不表示强度已平衡。

1. **普通前期：`EN-N-A1`**
   `method=RKF02`，`n=0`，`talents=[]`，`RC01x1`。
   `RC01` 为攻击 `+6`、同名上限 5；x1 合法，有直接攻击输入。
   无天赋仍可普攻、积怒并在门槛满足时使用怒技，不凭空获得阶段能力。

2. **精英一幕后段：`EN-E-A1`**
   `method=RKF01`，`n=1`，`J1-A`，`RC03x2 RC11x1 RR09x1`。
   `RC03` 为防御 `+5`、上限 5；`RC11` 为防御 `+2` 与获得护盾 `+6%`、上限 3；
   `RR09` 为防御 `+8`，已有盾返有效后每敌方主动作额外回怒 10、单件。
   `J1-A` 只在金刚功合法主修中提高本门造盾；`RR09` 不授予盾返，必须先有真实盾返输入。

3. **首领二幕：`EN-B2-A2`**
   `method=RKF02`，`n=2`，`J1-C/J2-B`，`RC01x2 RC10x2 RR01x1 RR05x1`。
   `RC01x2` 未超过上限 5；`RC10` 为攻击 `+2` 与怒技基础直接伤害 `+6%`、上限 3，
   x2 合法。`RR01` 为攻击 `+8`，普攻或怒技基础有效命中每主动作额外回怒 10、单件；
   `RR05` 为防御 `+8`，自身主动作完成后攻击叠层、最多 3 层、单件。
   `J1-C` 只提高归元怒技基础直接段；`J2-B` 只在轮尾追加自然回怒之外的 +10，
   不能把它误读成怒技伤害或额外行动。

4. **终战：`EN-F-A4`**
   `method=RKF01`，`n=4`，`J1-A/J2-C/J3-B/J4-B`，
   `RC03x3 RC05x3 RC11x2 RR07x1 RR09x1 RR05x1`。
   `RC03x3`、`RC05x3`（最大气血 `+25`、上限 5）和 `RC11x2` 均未超上限；
   `RR07` 防御 `+8`，首次怒技完成后本战怒气上限 `-15`、单件；
   `RR09`、`RR05` 均单件，触发仍按真实盾返和动作后叠层。
   `J2-C` 的最大气血项增加金刚功实际造盾；`J3-B` 只在首次被直接攻击完全破盾且存活
   后补盾；`J4-B` 取代怒技造盾并一次消费实际护盾换直接伤害，无盾仍可放基础怒技。
   这套敌方终战配置不使用传奇；它不证明玩家无传奇一定通关，后者仍须由固定参考盘实测。

敌方装备栏必须与掉落栏分开序列化。战前预览可以显示上述装备和层数，但战后奖励仍由
节点规则决定；敌人不会把 `RR07`、`RR09` 或其它装备转成玩家可领取候选。

## 6. 压力族与可读应对

普通敌人以建立成就感和读懂输入为目标，不是每场都把玩家推到极限。每个压力族至少有
两条公开可行的应对路径，不能要求单件唯一法宝；未定义净化资源不承诺存在，也不能把
“以后可能有净化”写成当前可用方案。

| 压力族 | 战前/战中提示 | 至少两条应对 | 禁止暗示 |
| --- | --- | --- | --- |
| 稳打护盾 | 预览每轮直接段、护盾窗口和盾返来源 | 先破盾再爆发；以持续直伤/耗盾换伤并保留治疗 | 敌盾不应无来源永久免疫 |
| 多段 | 显示段数、每段先后、每段是否可触发状态 | 堆防御/护盾承受；争先手或削弱单段并利用受击回怒 | 速度不变成额外段数 |
| 长 DOT | 显示施加轮、tick 时点、层数/持续未知项 | 争取短战击杀；以治疗/护盾拉长窗口 | 不承诺未定义净化或抗毒 |
| 恢复 | 显示治疗轮、有效目标和溢出出口 | 用开场爆发争取压过恢复；用持续伤害维持缺口 | 治疗不等于战外满血 |
| 叠 buff | 显示层数上限、动作后生效和覆盖时间 | 用早期输出缩短成长时间；补充减攻或续航承受成层后的压力 | 不把动作后层数追溯到刚结束动作 |
| 虚弱/破甲 | 显示作用属性、持续轮数和实际覆盖段 | 增强早期输出缩短覆盖；用不依赖受压属性的另一输出或防护来源 | 属性百分比不直接等于伤害百分比 |
| 削怒 | 显示开场/轮内请求、每轮上限和下一轮影响 | 增加普攻/轮尾回怒；选择普攻直伤或明示抗削怒来源 | 不靠先手取消本轮已锁怒技 |

这些应对是战前配装、选天赋与选路，不新增战中手动选目标或插招操作。DOT 是否经过护盾
按具体状态合同核验，不能默认护盾能抵挡所有持续伤害。

本轮不准入整场免毒、免盾或永久锁怒等直接报废流派的配置。新的阶段性减效也必须先定义
明确来源、持续时间与多种解法，不能仅凭“首领专属”进入目录。阶段转折最多一项可读变化，不要求为了首领而强行
新增 phase；如果现有卡面没有输入，先标待设计而不是偷偷给敌人新资源。

## 7. 训练盘与真实遭遇

训练盘使用足够耐打的固定木桩，目的为核对动作循环、逐段台账、怒气和状态时序；
不发节点奖励、不代表真实敌人胜率，也不用于证明 TTK。训练盘可把 `W=15` 作为统一观察窗，
但超过窗口仍是未决。

真实遭遇使用固定 stage 配置和固定 seed，必须记录胜利、死亡、未决、错误以及实际轮数。
敌方逻辑可以按公开的当前战斗状态分支，但不能按玩家拥有的 build、未取得奖励或隐藏
信息动态调参。战前预览后敌方配置冻结；奖励候选在正式生成、展示时固定保存，读档不重抽。

## 8. 配置 schema

每个敌方 fixture 至少具备下列字段；目标设计阶段所有未实现战斗量写 `null`，不得填估计
实测。`null` 字段用于说明“暂未定义/未测”的原因，不把空值当作零。

```json
{
  "fixture": "EN-E-A1",
  "stage_tier": "elite",
  "identity": "原创匿名沉鳞守将",
  "myth_source_ref": null,
  "method": "RKF01",
  "n": 1,
  "talents": [{"id": "J1-A", "unlocked": true}],
  "artifacts": [
    {"id": "RC03", "stacks": 2},
    {"id": "RC11", "stacks": 1},
    {"id": "RR09", "stacks": 1}
  ],
  "stats": {
    "attack": null,
    "defense": null,
    "max_hp": null,
    "crit_rate": null,
    "speed": null,
    "coefficients": null
  },
  "phase_source": null,
  "seed": "A1-S01",
  "target": {
    "rounds": [5, 8],
    "net_hp_loss_pct": [8, 14],
    "burst_warning_pct": 22
  },
  "measured": null,
  "null": {
    "reason": "target_design_before_runtime_fixture",
    "allowed": true
  }
}
```

逐事件记录还要带 `root_id`、`action_id`、`segment_id`、`owner_id`、`source_kind`、
`snapshot`、`actual`、`consumed`、`wasted` 与 `trigger_reason`。聚合数据必须能回溯到这些
事件；`measured=null` 不得由脚本自动当成 0。结果对象另存 `early_end`、
`win_rate`、`ttk`、`death_rate`、`undecided_rate`、`error_rate`、分位数、每轮峰值、
`prebattle_missing_hp`、`minimum_hp` 和 `dynamic_max_hp`。

## 9. 十门验收矩阵

| 门 | 覆盖 | 通过条件 |
| ---: | --- | --- |
| 1 | 十门功法与流派 | `RKF01-RKF10` 均能接入同一敌方 schema；功法位阶与敌人难度不混为一谈。 |
| 2 | ID、层数与来源 | 四套示例 ID、同名上限、天赋 `n`、唯一持有者和 `phase_source` 全可审计。 |
| 3 | 固定种子复现 | 同 segment、同 seed、同 loadout 的事件账、怒气、结果一致；读档不重发。 |
| 4 | 概率多 seed | 使用固定 seed 集合报告原始分布和分位数，不用期望值跨整数怒技门槛。 |
| 5 | 短/中/长战 | 至少覆盖 3/5、8/10、15 轮；超过 15 轮记未决，不自动失败。 |
| 6 | 低血与死亡 | 记录战前带伤、最低血线、死亡后停止后续效果；不伪造满血恢复或成功样本。 |
| 7 | 先后手与多段 | 交换速度仅交换先后；多段逐段回怒并验证不增加额外主动作。 |
| 8 | 七类压力机制 | 每类都能看见提示、至少两条应对、实际覆盖率与未触发原因。 |
| 9 | 免疫与新规则禁入 | 无来源免毒/免盾/永久锁怒、无隐藏 phase、无跨阶天赋、无未定义净化默认值。 |
| 10 | 真实结果与迁移边界 | 胜率/TTK 与 `P` 分开；奖励不从敌装复制；旧 `KF/FB` 未显式迁移前不得套用。 |

## 10. 迁移与未决风险

历史 `KF` 功法和 `FB` 法宝不能直接套进本页敌方配置；必须重新映射到新 `RKF/RC/RR/RL`
定义、怒气时序、层数上限和阶段来源。旧敌人没有完成迁移记录时，只能标
`migration_status="incomplete"`，不能假设它们已经符合七类压力或四档损耗带。

当前首轮仍未决：真实敌方属性系数、DOT tick/刷新和抗性公式、阶段转折实现、动态最大
