# V2：围绕核心法宝形成一局打法

> 2026-10-26。状态：可玩的实验版本，分支 `feat/v2-build-engine`，内容版本
> `shanhai-content-0.2`。V1 冻结在标签 `V1`、提交 `2f08f08`。
> 本实验不替换正式 `main`，也不宣称已达到 V1 的累计通关率目标。

## 第一原则：好玩、爽、想再开一局

系统数量、选择数量和低胜率都不能单独证明肉鸽感。这次实验的首要验收是：
玩家拿到一个东西后，能不能马上期待下一场，打完能不能看出它如何改变了打法。
允许有代价、需要配合的强组合形成压制，不为追求整齐的面板强度把所有流派磨平。

以下是试玩验收标准，不是已经通过的用户体验结论：

| 检查点 | 要观察的体验 | 不成立时怎么改 |
| --- | --- | --- |
| 第一场奖励 | 核心拿到后的下一战就有追击、施毒、造盾等实际变化 | 调整启动条件，不再追加等待节点 |
| 第一幕成型 | 玩家能说出自己的核心，以及下一件想要的搭配 | 缩短描述、改善候选和搭配入口，而不是增加教程 |
| 联动回报 | 支援与核心配合后的收益明显，战斗帧和来源账能解释 | 检查机制输入、触发次数和系数，不只抬总属性 |
| 中后期爆发 | 成型后可以打出高爆发、连续怒技或持续压制 | 保留局部超常收益，用成型成本和不同敌情约束 |
| 选择阻力 | 装备位和路线让人取舍，但没有反复切页的操作税 | 减少重复确认；必要时修改限制本身 |
| 失败与重开 | 能指出本局缺的环节，并愿意试另一种核心 | 改善败因与构筑反馈，检查是否只剩一种最优解 |

不增加每日任务、倒计时、延迟领奖或伪装概率来制造留存。事件继续保留即时结果、
明示代价和合理的未知后果。“上头”来自发现和兑现组合，而不是无法离开游戏的压力。

## 已实现的底层变化

### 持有不再等于生效

- 背包可以保留法宝；同时生效的是 **1 件核心 + 3 件辅器**。
- 同名普通法宝仍按原上限叠层，整叠占一个位置。
- 没有装备的法宝不提供属性、战斗效果或行旅收益；事件的持有条件仍能读取背包。
- 获得法宝时，兼容空位自动装备；满位则收入背包，不静默替换。
- 地图、领奖、坊市、休整和幕间可调整；进入敌情、事件或战斗后锁定。
- 替换预览明确显示失去的法宝与气血上限变化；换装不回血、不刷新候选或敌人。
- 行旅按节点入口时的装备和层数结算，且退出时必须仍持有并装备。中途取得不追补。

核心由 YAML 的 `equipment_role` 明确指定。六件普通核心与五件传奇占核心位，
其余三十三件为辅器。敌人也受相同装备数量上限约束，原有多核心配装已调整。

### 普通核心第一层就改变规则

下表只解释机制，完整参数以[普通法宝内容页](./content/artifacts/COMMON.md)为准。
原有属性、叠层与觉醒效果仍在；核心规则本身不随层数重复执行。

| 核心 | 获得的打法 | 代价或限制 |
| --- | --- | --- |
| 剑穗 `RC09` | 普攻后追加一次派生伤害 | 怒技基础伤害降至 65% |
| 雷纹印 `RC10` | 怒技完成后返还 20 怒气 | 承受直接伤害提高 12% |
| 铁壁符 `RC11` | 开场造盾，怒技将现有护盾转成额外伤害 | 消耗实际护盾，爆发与防护互相竞争 |
| 回春瓶 `RC12` | 普攻自疗，所有有效自疗额外转 60% 护盾 | 直接伤害降至 80%；满血溢出不算有效治疗 |
| 蛇纹瓶 `RC14` | 普攻施毒，怒技引爆全部预存自身毒层 | 消耗毒层，不能再吃同一份后续持续伤害 |
| 赤炎珠 `RC15` | 普攻燃烧，实际燃烧掉血按比例吸血 | 怒技基础伤害降至 80%；打盾不吸血 |

五件传奇沿用各自的转换、追击、开场或返怒能力，不再叠一个同名平行系统。
普通核心不是等待传奇的无效过渡物。无核心时的首次普通战奖励改为三个普通核心候选，
替换原奖励机会，不额外增加免费节点。

这些组合的身份不等于已经完成强度校准。例如同为金刚功，铁壁符偏耗盾爆发，
回春瓶偏回复与续盾，剑穗偏普攻追击。需要用同敌情的真实对照判断收益，
不能把来源账里的全部伤害直接当作“换装净提升”。

### 突破不再固定展示整层三列

保留十门功法和原有 120 张本门天赋，新增 12 张四阶共通洞见，定义在 `RULES.insights`。
每次突破从同阶池冻结 **两张本门天赋 + 一张共通洞见**，只可选择本次候选。

候选按种子、功法、阶数和洗点代次确定；读档、查看、切换功法不重抽。
付费洗点才推进代次。每阶仍只选一张，共通天赋不额外占用或增加突破次数。
共通洞见目前接入属性、开场护盾、轮尾回怒、行动后治疗与护盾等已有结算入口。
这是跨门派构筑的第一步，不等于已把全部本门天赋重做成自由技能池。

### 路线一次决定一段

四幕仍各走十一节点，终战一节点，总共四十五节点。
每幕起点后分为三段，每段三节点；进入一段后沿本路走完，段与段之间再分叉，
最后汇入首领。不再每一步都能左右切线拿走所有最有利节点。

生成器保留每条完整路径至少三场普通战、服务点各自可达、精英可绕过、
核心事件间距和全局额外精英额度。服务点可达不代表任意已选路线都能补救抵达。
后三幕沿用差异化功能节奏，本次更改的是连边承诺，不增加节点总量。

### 让构筑反馈紧跟战斗

- 命盘分开显示当前装备与背包，核心身份在奖励和详录可见。
- 手机奖励纵向排布，核心机制与代价先于长描述；完整规则留在详录。
- 战斗沿用已批准的人物素材、连续帧表现、伤害飘字和受击反馈。
- 战斗中的核心来源强调只对应我方实际出手，结算读取本场冻结装备。
- 简报保留核心与另一条重要贡献，不将伤害、护盾、治疗相加冒充一个战力分。
- 纯属性器物不因为没有触发次数就被标成“未生效”。

当前没有“移除这件法宝后重打”的玩家侧对照功能。来源贡献解释发生了什么，
不等同于因果净收益；不能将它包装成已经完成的逐件提升验证。

## 版本与验收边界

V2 的命途、构筑和回放存储键独立使用 `-v2`；不覆盖、不静默迁移 V1 存档。
缺失地图或使用旧连边拓扑的存档被拒绝。`measured` 继续为 `null`，
自动测试、固定种子通关和小样本统计都不能替代卡牌平衡结论。

主要验收入口：

```bash
npm test
npm run test:content
npm run test:v2
npm run simulate
npm run calibrate
BROWSER_URL=http://localhost:4178 npm run test:browser
BROWSER_URL=http://localhost:4178 npm run test:journey
BROWSER_URL=http://localhost:4178 npm run test:v2:ui
```

V2 仿真、校准和浏览器报告隔离在 `verification/shanhai/v2/`，
不覆盖 V1 的训练、留出或难度报告。固定真实流程种子为 `v2-functional-RKF01-0`；
完整桌面流程走四十五节点，手机流程验证第一幕十一节点。场景 fixture 验收只证明
控件与显示行为，必须和上述真实流程分开解释。

进入正式版前，仍需进行跨核心、跨起始功法的多种子配装校准和人工试玩。
V1 的 80% / 65% / 50% / 35% 是累计过幕目标；V2 改了装备、天赋与路线，
不能继承旧胜率。在校准阶段同时记录成型时点、核心采用与替换、通关分布、
压制性胜局和无成长感的失败，避免只盯着平均胜率。
