> 评审稿，更新日期：2026-09-21。

## 0. 边界与入口

本页只定义十门功法、合法突破天赋和相关资源的可复算强度预算，不替每张卡指定最终系数。
法宝自身的位阶、旅途 `J`、综合 `U` 及 44 个 ID 的成对复标见
[法宝位阶战斗与旅途基线](./ARTIFACT_BASELINE.md)；本页继续提供共享 `D0/L0/H0`、
事件账本和 `P` 的权威定义。

功法职业、属性边界和十门名称见[新版总纲](./README.md)与[功法职业化方法](./METHODS.md)。

怒气上限、开场、普攻、受击、轮尾和削怒只引用[新怒气合同](./ARTIFACT_SYSTEM.md#怒气上限与怒技节奏)。

旧功法树、旧法宝数值和旧稿平衡结论不自动迁移；本页不把 `P` 当作胜率、TTK 或全局排名。

| 术语 | 含义 |
| --- | --- |
| 普通参照 | 无天赋、无装备、无行旅临时准备的中性角色。 |
| 同境界 | 被测盘和普通参照使用同一境界、基础属性成长和动作权限。 |
| 目标值 | 设计阶段希望验证或调整到的数值，不是引擎输出。 |
| 实测值 | 固定种子 fixture 运行后记录的结果；当前文档不填实测值。 |
| 中性盘 | 测试窗完整存活、`L>0` 且可与普通参照直接比较的样本。 |

### 0.1 设计总览

本页把五维强度预算和五类战斗效果接成同一条可审计链：

```text
卡面输入
  → 轮初锁动作 / 逐段执行
  → 原始事件与修正后事件
  → 实际承伤、入血、有效治疗、护盾余额和状态覆盖
  → 派生事件（只读已记录结果，不沿自身递归）
  → 轮尾持续伤害、死亡、怒气与上限结算
  → fixture 曲线、事件台账、D/L/H/P 与未兑现资产
```

对玩家，基线只需要回答“这次伤害打进了多少、治疗救了多少、盾挡了多少、状态覆盖了
多久、为什么没有触发”。对开发，任何结果都必须能沿 `root_id/action_id/segment_id/
owner_id` 回到一次唯一事件，并区分目标输入、已兑现结果、浪费和仍待定义的 fixture
参数。本文补齐的是验收合同，不代表卡面倍率、持续效果 tick 或抗性公式已经定稿。

## 1. 统一测试参照

### 1.1 测试窗与共享锚点

首轮统一目标测试窗为 **十五回合**，记作 `W=15`；它只定义基准观察上限，不暗中决定实际游戏超时胜负。

真实战斗可以提前结束；死亡、胜利和满窗存活分别记录。测试窗外才发生的伤害、治疗、护盾、毒火或回怒不计入本轮基线。

每次对照使用同一参考普通功法、同一境界的固定基础角色、同一敌方配置和同一随机种子。

所有功法、天赋树和同一轮对照都共用唯一一份主原始参照 `D0/L0/H0`，不得按功法、
天赋树或被测配置各自重建参照再归一化，否则稀有优势会消失。不同压力盘可以保留自己的
原始事件账，但不另造一份主参照。

| 项目 | 中性目标 |
| --- | ---: |
| 普通参照的归一化输出 `D` | 100 |
| 普通参照的归一化有效承伤/净有效生命损耗 `L` | 100 |
| 普通参照的归一化最大气血指数 `H` | 100 |

三个一百是共同锚点的目标表示，不是某次测试已经测出的数值；唯一主原始参照
`D0/L0/H0` 仍须由统一 fixture 确定，不能直接填成一百，也不能为每门功法分别建立
原始基线。无天赋、无装备、无行旅临时准备的盘用于建立锚点；功法基础动作仍合法运行。

同境界自然属性成长同时进入普通参照和被测盘，比较天赋前先排除共同成长。

### 1.2 训练压力与早结束

训练敌方应足够耐打，使大多数满窗样本不会因击杀过早停止输出；训练盘测动作循环，不是一次真实战斗的胜负压力。

真实敌人、高压敌人和短战另设 fixture。提前死亡导致输出截断时标记 `early_end=death`，不能把较低 `L` 当成优秀存活。

提前击杀标记 `early_end=victory`，不补入未发生的后续输出；脚本或引擎错误标记 `early_end=error`，不进入中性盘。

### 1.3 概率与种子

概率效果使用固定种子集合，报告原始分布和目标分位数；同一配置的种子、敌方初始配置、
行动规则和测试窗必须固定，但削怒改变的实际敌方出招必须重新计算，不能锁死为同一动作序列。

不能用期望回怒跨过整数怒技门槛，也不能用期望触发次数替代真实动作次数。分位数不能掩盖某种子提前死亡、怒技少一次或条件不成立。

## 2. 主强度尺

### 2.1 `D/L/H` 定义

每个 fixture 至少保留逐回合曲线、直接伤害、派生伤害、持续伤害、真实入血、敌盾消耗和
有效治疗。`D` 使用同一口径计算普通参照和被测盘：

```text
D_raw = 实际敌方入血 + 实际消耗敌方已有护盾
D0 = 参照敌方入血 + 参照实际消耗敌方已有护盾
D = D_raw / D0 × 100（仅当 D0 > 0）
D_HP = 被测配置实际敌方入血 / 参照实际敌方入血 × 100（仅当该分母 > 0，否则为 null）
L_raw = 外来实际入血 + 自伤实际入血 - 有效自疗
L0 = 普通参照同口径净有效生命损耗
L = L_raw / L0 × 100
H = 被测配置固定起始最大气血 / 普通参照固定起始最大气血 × 100
```

`D` 只计真正改变敌方已有护盾或气血的量：不计我方生成的护盾、不计未命中的空中输出、
不计过量击杀、不计窗口末尚未兑现的毒火或燃烧。敌方护盾被一段伤害真实消耗的部分计入
`D`，即使该段随后又造成入血，也按两个不同账项各计一次，不把同一数值重复加回。`D_HP`
是诊断子指标，不替代 `D`；它的入血分母为零时仅记 `D_HP=null`，并注明
`reason=reference_hp_damage_zero`，不影响在 `D0>0` 时计算可比较的 `D`。只有 `D0=0`
才表示该 fixture 无法计算 `D`，不能用零填充或因此把其它独立诊断项一并判为无效。
文档中的原始量（`D_raw/L_raw`）与归一化指数（`D/L`）必须分栏记录，不能把原始账
直接当作正式参照指数。

一次攻击必须把下列量分开记录：

| 台账项 | 含义 | 是否直接进入 `D` |
| --- | --- | --- |
| `attack_raw` | 已读取卡面明示基础属性与招式/效果系数后的原始量；尚未施加效果修正、暴击或减免 | 否 |
| `attack_modified` | 合并合法效果修正后的待结算量 | 否 |
| `mitigated` | 经过防御、虚弱、破甲或其它已声明减免后的量 | 否 |
| `shield_absorbed` | 真实从目标已有护盾扣除的量 | 是，作为敌盾消耗 |
| `hp_damage` | 真实扣除目标当前气血的量 | 是，作为敌方入血 |
| `overkill` | 目标气血归零后仍会产生的过量量 | 否 |

`source_kind` 必须标记 `direct`、`derived`、`dot` 之一；每条事件另有唯一的
`root_id`（原始效果链）、`action_id`（主动作）、`segment_id`（逐段）和 `owner_id`
（产生该事件的角色/状态）。毒火、燃烧、反震、追加和治疗转盾都不能因为是派生事件而
丢失自己的来源链。参考盘和被测盘使用完全相同的字段与去重规则。

`L_raw` 的原始账为：

```text
L原始损耗 = 外来实际入血 + 自伤实际入血 - 有效自疗
```

护盾在入血前抵消伤害，所以不在 `L` 中再减一次；主动耗盾导致的后续承伤变化也要记入，
不能只计换出的伤害却漏掉防护损失。真实入血伤害此处只含外来伤害，自伤单列，避免重复相加。

有效自疗只算真正填回气血的部分，溢出治疗不进 `L_raw`；期末剩余护盾不制造负损耗。动态最大
气血、临时变身和上限变化另记 `dynamic_max_hp`、发生时点和当前气血截断，不能用 `P`
掩盖死亡、提前胜利或 `L<=0`。

`H` 读取同一种固定起始最大气血基准。战内涨血、临时变身和特殊状态另设动态生命 fixture，不伪装成静态 `H`。

### 2.2 综合预算尺

只有 `L>0` 且完整存活整个窗口的可比中性盘使用：

```text
P = D × H / L
```

普通参照目标为 `D=100、L=100、H=100、P=100`。若 `L<=0`，标记“无损/样本饱和”，改用对所有配置一致的更强压力盘，禁止 clamp 成一伪装可比值。

报告必须同时展示 `D`、`L`、`H` 和曲线；`P` 不是胜率或 TTK 证明，也不用于给所有真实对局硬排强弱。

| 目标输入 | `P` 算术示例 |
| --- | ---: |
| `D=100,L=100,H=100` | 100 |
| `D=110,L=88,H=100` | 125 |
| `D=100,L=100,H=125` | 125 |
| `D=104.5,L=95,H=100` | 110 |

最大气血目标 `H=125` 且 `D/L` 保持普通目标时为 `P=125`；若它同时带治疗或盾返，必须用实际总账核算，不能逐条免费加分。

### 2.3 事件账本与去重

每条效果事件至少保存 `raw`、`modified`、`actual`、`wasted`、`snapshot`、`consumed`
和 `trigger_reason`。`actual` 只能在目标状态真实改变后写入；没有输入、目标已死、满血、
盾已满、状态已过期或能力被清除时，写零并写明原因，不能静默丢事件。

同一 `root_id` 下可以有合法跨能力串联，例如攻击造成实际燃烧、燃烧实际入血触发回怒；
但派生事件必须读取父事件已经登记的实际结果，不能沿自身输出重入自身。一次护盾、一次
治疗溢出、一次中毒层或一次怒气收入只能消费一次。若多个能力读取同一结果，必须记录各自
的读取标记，而不是把原结果复制成多份伤害或治疗。

## 3. 五类效果合同

五类效果都必须写清输入、修正、实际结果、结算时点、浪费出口和来源链。效果本身不另造
“治疗强度”“护盾强度”“状态强度”等基础属性；能力修正只读取卡面明示的攻击、防御、
最大气血、暴击率或速度，或者读取已记录的同类实际结果。以下“预算算例”都是非卡牌数值，
只用于说明账本和反推方法。

### 3.1 恢复

- **输入与计算**：记录 `heal_raw`、合法治疗修正和目标当时缺口。先合并并修正总治疗，
  再拆成 `effective_heal = min(heal_modified, missing_hp)` 与
  `overflow_heal = max(0, heal_modified - effective_heal)`；不能先按缺口截断再套倍率。
- **时序与浪费**：治疗在其声明的动作段或派生段结算；已死亡目标不再接受战斗内治疗。
  满血时仍记录 `trigger_reason=full_hp`，但这只说明本次没有有效回血，不等于整份溢出
  都是浪费。若卡面声明了转换出口，先把溢出独立登记并转入该出口；只有未被转换的部分
  才记作 `overflow_wasted`。有效治疗进入 `L_raw` 的负项，溢出不进入 `L_raw`，同一份
  溢出也不能同时作为有效治疗再触发第二个出口。
- **公共边界**：`RR02` 只读取每个自身主动作的首次有效自疗并按卡面比例造盾，原治疗
  保留；`RR12` 只读取有效自疗，不读取溢出；`RL01` 把同一份真实溢出改走一个护盾
  出口，不能同时转成伤害或施毒。战外治疗独立结算，只回血，不生成战斗怒气、毒火、
  下一战护盾，也不触发 `RR02/RR12`。
- **预算算例（非卡牌数值）**：当前气血 `70/100`，原始治疗 `30`，总治疗修正 `+20%`
  后为 `36`，有效治疗 `30`、溢出 `6`。`RR02` 若读取有效治疗比例 `50%`，只造盾
  `15`；`RL01` 若启用，则同一 `6` 只能作为其护盾出口。若匹配基线外来入血为 `100`，
  有效自疗 `20` 将 `L` 从 `100` 降为 `80`，对应 `P=125`，不能再把溢出另加 25 点。

### 3.2 护盾

- **输入与守恒**：分别记录 `shield_raw`、修正后的 `shield_modified`、实际入池
  `shield_added`、逐段 `shield_absorbed`、主动 `shield_consumed`、过期
  `shield_expired` 与窗口末 `shield_remaining`。同一盾池必须满足：

  ```text
  期初盾 + 入池 - 吸收 - 主动消费 - 过期 = 期末剩余盾
  ```

  溢出入池、不同盾层和转盾出口的截断都要有独立原因；生成盾不是伤害，也不是已吸收。
- **时序与浪费**：造盾在声明的原始事件或有效治疗派生后入池；敌方直接攻击逐段先消耗
  盾再入血；主动耗盾只在卡面声明的动作时点消费；过期在声明的轮尾/状态时点处理。
  窗口末的 `shield_remaining` 是未兑现资产，不转成 `D` 或负 `L`。主动消费不得计入
  `shield_absorbed`；若耗盾转伤，必须同时记录消费事件和后续敌方实际入血/盾消耗，
  再与“不消费、保留防护”的同 fixture 比较后续风险。
- **公共边界**：我方护盾吸收降低后续外来实际入血，但不把吸收量再从 `L` 中扣一次；
  敌方已有护盾被我方伤害真实消耗才计入 `D`。护盾与气血同一受击段同时发生时，受击
  回怒只登记一次，沿用公共怒气合同。
- **预算算例（非卡牌数值）**：入池 `22` 的盾承受 `30` 外来伤害，记录吸收 `22`、入血
  `8`、剩余 `0`；若先主动消费 `10` 换出伤害，必须把 `10` 记为消费而不是吸收，并把
  后续同样 `30` 的攻击按较少盾量重新计算。若其余输入与基线一致，真实吸收 `20` 可使
  `L=100→80`，对应 `P=125`；耗盾换来的输出只有在实际打进敌方盾/血时才进入 `D`。

### 3.3 持续伤害（DOT）

- **输入与计算**：每个状态声明施加来源、初始层数、每层量或总量、tick 间隔、持续轮数、
  层数上限、刷新/叠加/替换、快照或动态读取、可否被清除和可否主动消耗。`snapshot`
  在施加时锁定其明示输入，`dynamic` 在每次 tick 读取当前输入；未声明时两者均不成立。
- **时序与浪费**：施加事件本身不等于已造成伤害；只有在窗口内实际 tick、经过目标当前
  护盾/气血结算的 `hp_damage` 或敌盾消耗才记入 `D`。轮尾先结算 DOT 及其合法派生，
  再判死亡，再结算怒气；目标死亡、战斗结束、提前胜利或窗口结束后未发生的 tick 全部
  写入 `unused`，不补算。每个 tick 的层数、刷新和剩余时长在事件快照中可追溯。
- **未定项处理**：毒与火的 tick 顺序、同名层是否加算、刷新是否延长、上限、净化/清除
  和抗性公式都不是本页暗定的正式机制；必须作为 fixture 显式参数，并在报告的
  `fixture_metadata` 中标记。没有该参数，不能宣称“五毒”或“御火”的所有状态规则已定。
- **预算算例（非卡牌数值）**：声明 DOT 总量 `30`，但三回合短战只实际 tick `10`，
  则 `D` 只增加真实 `10`（再按目标盾/血拆账），未兑现 `20` 写入 `unused`；不能按
  “施加了 30”或“持续效果统一加 25%”计分。若 tick 前致死，后续 tick 与派生均不发生。

### 3.4 增益（buff）

- **输入与计算**：记录来源、目标、改变的属性/动作、层数、持续时间、上限、快照/动态
  读取、叠加/刷新/替换和清除条件。增益不单独送分；只在实际覆盖的伤害、承伤、最大
  气血或动作事件上产生差值。最大气血增益造成的当前血量截断和 `dynamic_max_hp` 单列。
- **时序与浪费**：增益在获得后才覆盖后续事件，不追溯已经结束的动作；满层、过期、无
  合法目标或战斗结束时的未用层写 `unused`。条件覆盖率和时间覆盖率分开：
  `conditional_coverage` 是条件满足的可触发事件占比，`time_uptime` 是状态存在的时间
  占比，二者不能互相替代。
- **公共边界**：`RR05` 在自身主动作完成后才叠攻击层，刚结束的动作使用叠层前快照，
  不得追溯修改该动作；后续动作才读取新层。必须区分**属性修正**和**伤害类型修正**：
  攻击属性增益影响所有卡面明确读取攻击的公式，例如普攻/怒技直接段、御火/五毒以攻击
  供给的燃烧/中毒，以及卡面明示攻击参与的盾返；普攻或怒技专属百分比则只放大对应
  动作的基础直接段，不自动放大毒火、盾返或法宝追加。任何未声明读取攻击的效果都不因
  “攻击增益”凭空获得输入。
- **预算算例（非卡牌数值）**：十个同类直接段中只有五个被增益覆盖，基线合计实际输出
  `100`，覆盖段从每段 `10` 变为 `12`，则实测增量为 `10`、`D=110`，时间覆盖率
  可能为 `50%`；不能把卡面“+20%”直接写成总预算 `+20` 或 `+25`。若增益改变动作
  数量，必须另报普攻/怒技次数和早结束原因。

### 3.5 减益（debuff）

- **输入与计算**：记录目标、作用属性或行为、层数、持续时间、上限、快照/动态读取、
  叠加/刷新/替换、抵抗和净化条件。减益不单独送分，按实际覆盖事件改变 `D`、`L`、
  `H` 或动作锁定，并报告 `conditional_coverage` 与 `time_uptime`。
- **虚弱与破甲**：虚弱、破甲应进入已声明的敌方攻击/防御计算位置，再由 `hp_damage`、
  `shield_absorbed`、行动结果反推效果系数；不能把“减属性百分比”直接当成“增减伤百分比”。
  破甲打在敌方护甲上的实际结果、虚弱改变敌方下一次攻击的实际结果分别记账，不能合并
  成一个抽象状态分。
- **时序与浪费**：轮初动作锁只锁招式和怒技实际支付值，不把本动作所有数值锁死；各段
  按自身声明的 `snapshot` 或 `dynamic` 读取当前属性与状态。动作后新叠的层不追溯已经
  结算的段；同一动作后续段是否可读取新状态，必须由 fixture 明确声明，未声明则记入
  `unknown`，不一律禁止。清除、抵抗、目标已死、无可影响动作和过期都写入
  `trigger_reason`。削怒请求沿公共怒气合同登记和结算，不因为是负面效果就自动算成持续
  减益。
- **预算算例（非卡牌数值）**：十个同类敌方攻击段中四段被虚弱覆盖，基线实际入血为
  `100`，该四段在明确的承伤 fixture 中合计少入血 `10`，则 `L=90`，效果贡献由这
  `10` 个实际点反推；不能把卡面“敌攻 -20%”直接记成 `L=-20`。破甲同理，必须用
  被测盘和无减益盘的真实敌盾消耗/入血差值。

### 3.6 五类效果的同预算对照

以同一普通参照 `D0/L0/H0` 和同一十五回合窗口为前提，先看实际账，再看综合预算：

| 方案 | 实际结果目标 | `D` | `L` | `H` | `P` | 计分边界 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 纯输出 | 实际敌方入血/敌盾消耗增加 | 125 | 100 | 100 | 125 | 不把空中输出或过量击杀算入 |
| 纯有效恢复 | 有效自疗使净损耗降低 | 100 | 80 | 100 | 125 | 溢疗另记，不重复计分 |
| 纯有效护盾 | 盾真实吸收后减少后续入血 | 100 | 80 | 100 | 125 | 生成盾、剩余盾和主动耗盾不等于吸收 |
| 混合输出与防守 | 伤害与治疗/盾的实际合计 | 110 | 88 | 100 | 125 | `D/L` 联立，不能每项各加 25 |
| 起始最大气血 | 起始最大气血提高 | 100 | 100 | 125 | 125 | 战内动态最大气血另列，不伪装静态 `H` |

该行只表示静态开战时的起始最大气血；战内动态最大气血、临时变身和当前气血截断仍须
使用独立动态生命 fixture，不得回填为静态 `H`。

DOT、buff、debuff 不预设“每项增加 25%”。先以成对 fixture 的实际差值反推效果系数：

```text
效果实际贡献 = 有效果盘实际账 - 无效果盘实际账
系数或覆盖价值 = 效果实际贡献 / 被该效果合法覆盖的输入量
```

成对比较必须锁定敌方、种子、动作规则和窗口；若效果改变动作数量、早结束或目标状态，
同时报告这些中介结果。单因素消融用于诊断来源，不把各项差值强行相加为一张“理论满分”。

## 4. 天赋预算与稀有度

### 4.1 每次突破

每次合法突破提供一次基于本稀有度初始预算的 **目标百分之二十五增量**，不是每阶把上一阶 `P` 乘以 `1.25`。

```text
P目标 = 100 × rarity × (1 + 0.25 × n)
```

其中 `n` 是已完成的合法突破层数，目标范围为 `n=0..4`。稀有度总预算只计算一次，不能同时把伤害、血量和减伤各乘一遍。

| 稀有度档 | `rarity` 目标倍率 | 口径 |
| --- | ---: | --- |
| 普通 | 1.00 | 基准预算 |
| 稀有/珍稀 | 1.10 | 同一档，不新增第四档 |
| 传奇 | 1.25 | 总预算只进入一次 |

### 4.2 各层目标

| 突破层数 `n` | 普通 `P` 目标 | 稀有/珍稀 `P` 目标 | 传奇 `P` 目标 |
| ---: | ---: | ---: | ---: |
| 0 | 100 | 110 | 125 |
| 1 | 125 | 137.5 | 156.25 |
| 2 | 150 | 165 | 187.5 |
| 3 | 175 | 192.5 | 218.75 |
| 4 | 200 | 220 | 250 |

同境界自然成长已在两组共同输入中，必须排除后再比较天赋。一阶验收容差先建议为目标 `P` 的正负百分之五，可在实测后调整。

普通卡每阶边际预算建议先落在二十至三十个普通点之间，稀有和传奇按总倍率同比缩放。

条件卡须分别列理想局和不利局；理想值不能充当常规局目标。预算可在输出、承伤、血量、治疗、护盾和循环间重分配，不要求普通功法 `D` 都为一百。

## 5. 纯输出与纯防御校准

### 5.1 `100→75` 的含义

受击从一百变七十五是约三分之一的生存增益，不是百分之二十五；固定 `D=100、H=100` 时目标 `P≈133.33`。

同等二十五点综合预算的纯防御基准先用 `100→80`：

| 层数 | 纯输出 `D` 目标（`L=100,H=100`） | 等价承伤 `L` 目标（`D=100,H=100`） |
| ---: | ---: | ---: |
| 0 | 100 | 100 |
| 1 | 125 | 80 |
| 2 | 150 | 66.67 |
| 3 | 175 | 57.14 |
| 4 | 200 | 50 |

不能每阶固定减二十五并把最终承伤压到零。`L=75` 可作高档条件结果或取舍结果，不是普通一阶标准。

### 5.2 生命、治疗、护盾

最大气血目标 `H=125`、`D/L` 保持普通目标时可达 `P=125`；同时增加治疗、造盾或盾返时只能按实际总账核算。

治疗溢出、期末剩盾和未兑现状态不得逐条再送综合预算。金刚功的防御、造盾和盾返三重收益必须拆账，验证是否超过总目标。

### 5.3 边际收益、整树叠加与预算分层

每张天赋先做单因素边际测试，再做合法整树叠加。边际 `P` 用同一参照和同一 fixture
计算：

```text
边际P = P(加入该项) - P(移除该项)
整树P = P(主修基础 + 合法天赋组合)
```

边际结果只用于回答“这一项实际贡献多少”，不能把每张卡的边际值直接相加来宣称整树
达标。早发怒技、延迟毒火、复合防御、最大气血同时带来的多个收益，必须在整树实际
时序中结算：早发可能增加输出但消耗普攻回怒，延迟效果可能在短战未兑现，防御可能
同时改变盾吸收、盾返和治疗窗口，最大气血可能同时提高 `H`、治疗缺口和造盾输入。
这些交互不能用单因素结果免费叠加。

主修基础、天赋树和法宝分别列预算来源：

| 预算层 | 输入范围 | 报告方式 |
| --- | --- | --- |
| 主修基础 | 基础普攻、怒技、固有状态和公共动作 | 以无天赋、无装备普通盘建立全局唯一的 `D0/L0/H0` |
| 天赋 | 合法四层 A/B/C 选择及其机制改写 | 单卡边际、合法整树、理想/不利覆盖分别报告 |
| 法宝 | 普通叠层、稀有能力、传奇转换 | 单独预算盘，与主修/天赋盘分开，再做明确的合盘压力测试 |

法宝不能把天赋缺口偷偷补进主修预算，主修也不能把法宝实际贡献标成天赋达标。合盘
只说明玩家最终组合的实际结果，不改写各层归属。

## 7. 回怒强度的动作会计

回怒强度按实际替换的动作和结果核算，不把回怒值百分比直接当伤害百分比。

新怒气合同的目标来源为开场五十、普攻二十五、有效受击段五、轮尾自然十；这些仍须按公共合同的登记时点结算。

普通无返怒的十五回合算术参照为四次怒技（目标回合 `3/7/11/15`）、十一次普攻；若普攻目标伤害四、怒技目标伤害十四，则 `11×4+4×14=100`，只是示例。

一次额外怒技会替代一次普攻，只增加 `14-4=10`，不是增加十四。若纯怒技强化希望总量增加二十五，四次怒技各须增加六点二五，即示例怒技系数目标增加约百分之四十四点六四。

归元固有返怒目标为实际消耗的百分之二十。十次普攻、五次怒技，普攻四、怒技十二的
示例总量为 `10×4+5×12=100`。

`J1-A` 目标为怒气上限减十，可能改变首发但仍为五次怒技，十五回合示例输出不自动增加。

再选 `J2-C`，返怒比例目标增加二十个百分点；若成为七次怒技、八次普攻，示例为 `8×4+7×12=116`，不能宣称两阶已达一百五十。

当前资源提案标记“待校准”：应结合实际附效、早发收益、天赋预算或卡面修改；禁止为通过目标偷偷增加隐藏伤害。

每个回怒方案至少记录目标三回合、五回合、十回合曲线、首怒回合、怒技次数和普攻次数。

开场、控怒、速度时机和行旅天赋不能被十五回合木桩抹平；行旅收益使用独立节点预算，不混入战斗二十五点。

削怒不是“每一点固定换多少伤害”的兑换率。对真实敌人，先按本轮已锁动作执行，再在轮尾
按公共合同结算削怒；下一轮必须用新的敌方怒气、上限和行动优先级重新锁定动作。它不能
回溯取消本轮已锁招、改变已支付成本，也不能把同一轮未发生的敌方怒技假设成伤害。若
削怒造成早结束或少一次敌方动作，报告真实动作差异、敌方入血和 `early_end`，不填一个
固定削怒伤害系数。`RR05` 的动作后叠层同样只覆盖后续动作，不追溯刚结束的主动作。

### 7.1 时序合同

所有效果 fixture 都按以下固定顺序记录 checkpoint；没有运行时实现时，先用确定性样例
验证账本，不为未定状态偷偷选择一个默认机制。

1. **轮初锁定**：读取上一轮已结算怒气、当前上限和临时状态，同时锁定双方本轮动作与
   怒技实际支付值。轮内新增回怒、削怒、buff、debuff 不改变本轮已锁动作。
2. **逐段执行**：按动作段顺序读取该段允许的 `snapshot`，执行原始事件、修正、减免、盾/
   气血结算，再登记唯一 `segment_id`。追加、反震、治疗转盾和 DOT 等确定性派生只能
   读取已经记录的父事件实际结果，不沿自身输出递归。
3. **即时终止**：角色死亡或非致命败北立即停止其后段、后续治疗、派生和本轮未结算收入；
   敌方死亡也立即停止其后续动作与状态 tick。早胜、早死都保留已经发生的事件，不补算
   目标窗口剩余内容。
4. **轮尾结算**：动作完成后先执行本轮声明的 DOT、派生及其死亡判定，再处理动态上限/
   状态变化，最后按公共怒气合同合并支付、收入和有效外来削怒。持续伤害造成的死亡先于
   回怒，角色已不在战斗中则该轮未到结算点的收入丢弃。
5. **窗口结束**：记录未兑现的 DOT、未吸收的盾、未用层数和未触发条件；结算末残余状态
   只是未兑现资产，不再给 `D/L/H/P` 加分，也不追溯改变已结算动作。

### 7.2 Fixture 配置清单

每个新样例必须标注 **“预算算例/fixture，不是卡牌数值”**，并保存以下配置；缺值只能写
`null` 并进入 `unknown`，不能由审计脚本自行补全：

| 配置项 | 必须显式写入 |
| --- | --- |
| 测试窗与早结束 | `target_rounds`、实际轮数、`early_end`（`death/victory/error/null`） |
| 种子与动作 | 固定种子、离散概率结果、敌我初始状态、速度和轮初动作锁 |
| 伤害与资源 | 防御/减免位置、护盾吸收顺序、治疗顺序、怒气来源及轮尾顺序 |
| DOT | tick 时点/顺序、快照或动态、层数、刷新、时长、上限、清除、主动消耗 |
| 护盾 | 生成修正、入池截断、吸收、主动消费、过期时点、剩余守恒 |
| buff/debuff | 覆盖条件、层数、刷新/替换、持续时间、清除、属性读取和动作影响 |
| 抗性/净化 | 只有 fixture 明示能力时才填写公式、来源、向下取整和覆盖事件 |

这些参数是测试输入，不是对运行时尚未决定规则的承诺。尤其不能因为一个样例选择了
某种 tick 或刷新顺序，就把它写成所有毒火、护盾或状态的正式共通机制。

| 致死先于治疗 | `3/5` | 死亡立即停止后续动作/治疗/派生/怒气，标记 `early_end=death` | 复活、非致命败北（未有明确能力时不测） |
| 耗盾损失 | `5/10` | 主动消费与吸收分开，耗盾转伤实际入血/敌盾，和保留防护的成对比较 | 具体耗盾卡面未定的替代关系 |
| 短战 DOT | `3/5` | 施加未 tick、tick 一次、提前胜利、窗口末 `unused`，不补算未来伤害 | 长时长刷新与清除组合 |
| buff 叠层 | `5/10/15` | 叠层上限、动作后生效、`RR05` 不追溯、条件覆盖率/时间覆盖率分离 | 未声明的快照/动态读法 |
| buff 刷新过期 | `3/5/10` | 刷新、替换、过期、满层和无目标的 `trigger_reason` | 同时多来源的优先级 |
| 破甲/虚弱 | `5/10/15` | 覆盖前后实际敌盾消耗、入血、承伤和行动变化；按真实差值反推，不把属性百分比当增减伤 | 抗性与净化，除非 fixture 明示能力 |
| 抗性/净化 | 按明确 fixture | 只有配置明示抗性或净化能力时才测抗性、清除、向下取整和实际覆盖 | 没有明示能力时一律记为未验，不暗加通用抗性 |
| 削怒对抗 | `5/10/15` | 轮初锁招、轮尾削怒、下一轮真实敌方重算、早结束和动作差异 | 本轮已锁招不改变；不按每点削怒固定换伤；独立效果 fixture 当前只静态接入实际事件来源，未覆盖运行时敌方重算 |
| 概率与离散动作 | 全窗口固定种子 | 固定种子下逐次触发、怒技/普攻整数次数、分布、早死亡/早胜利 | 期望值替代真实动作、未覆盖的新种子 |

短战是额外场景，不取代十五回合统一目标窗。配置分开报告：无装备基础盘、同一功法单天赋 A/B/C、合法混选树、等预算普通法宝成长盘、传奇兼容盘。

六层普通法宝不能算作天赋本体。金刚防御、造盾、盾返三重收益、治疗溢出、概率分位数和速度实际时机必须单独测。

## 10. 实现前置与复算计划

运行时需先稳定同境界基础属性、固定起始最大气血、敌方动作、伤害会计和持续效果终止时点。

验证器需支持固定种子、分位数、早结束状态、`L<=0` 压力盘切换，以及按动作替换而非只按怒气收入统计循环。

独立算术审计已经提供，可在仓库根目录运行：

```text
node verification/power-budget/audit.mjs
node verification/rage-economy/audit.mjs
```

第一条命令复核十门 `D/L/H/P` 表、稀有度目标、纯防御换算和十五回合动作示例；
第二条复核怒气资源结算、开场与削怒、先后手和条件来源。它们不运行真实伤害引擎，
不验证种子胜率、实战提前死亡或全部卡牌预算达标。

效果账本的独立 fixture 与审计脚本已经提供：

```text
verification/power-budget/effects.mjs
verification/power-budget/effects-audit.mjs
node verification/power-budget/effects-audit.mjs
```

它们验证本文明确样例中的伤害/治疗/护盾/状态账本和时序，并输出事件账与原始效果量；
不把原始量自动转换成共享参照下的正式 `D/L/H/P` 指数，不能替代运行时实装、全卡模拟、
真实种子胜率或最终平衡。当前脚本把实际事件中的直接受击段、有效自疗和有效 DOT 等
有限来源静态转换为 rage 输入；没有 `lockRound` 下的动态敌方伤害重算，也没有运行时
削怒后下一轮敌方动作/伤害的真实对抗。因此动态敌方伤害与削怒对抗仍是运行时及后续
对抗验收项，效果 fixture 的状态样例通过不等于卡牌平衡已通过。新增脚本仍须保持上面的
算术审计与怒气审计命令可用。

缺少运行时 fixture 时必须保持 `measured:null`。实现前不得把本文目标值写回卡面、法宝目录或战斗运行时作为已确认常数。

最终以可复算原始 fixture、逐回合台账和真实对手压力盘验收；实际测试后可调整阈值。
