# 四幕难度校准

> 2026-10-23。沿用已认可的 UI、美术与连续帧战斗，只调整公开内容参数与一处参数读取。
> 本页记录自动策略模拟，不是人类玩家胜率。所有内容实测字段仍为 `null`。

## 概率口径

四幕目标为同一开局样本的**累计通过率**：80%、65%、50%、35%。
分母从开局到第四幕始终不变，不能将这四个数理解为逐幕条件胜率再相乘。
按目标反推，进入各幕后的条件通过率约为 80%、81.3%、76.9%、70%。
第四幕通关即进入第五幕；第五幕只有一场独立终战，另列入场后的胜率。

目标存于 `content/shanhai/rules/RULES.yaml` 的
`calibration.cumulative_act_pass_rates`，报告直接读取，不另设隐藏难度参数。
保留四幕各十一节点、加一场终战的四十五节点流程，不增加突破或跨幕免费回血。
敌人不根据玩家功法、构筑、已获奖励或连胜动态变强，也不以十五回合强制判负。

## 调整内容

- 三十四个敌人的基础攻击重新定标，第三、四幕与终战增加固定气血，保留原有身份、
  功法、天赋、装备和公开机制。
- 金刚功降低持续造盾与首次破盾后的续盾，使承伤仍会消耗气血。修复法相护体读取
  YAML 增量的逻辑，移除固定使用旧 12% 的运行时常数。
- 回春功降低基础与天赋治疗、高阶治疗转盾收益，保留有效治疗、溢疗、净化和转化出口。
- 归元诀提高基础攻击与怒技伤害，让没有固有回血的进攻路线能减少敌人出手次数。
- 养剑诀提高基础剑击与剑势收益，同时收紧按剑势持续造盾的系数，避免双方长时间
  无法结束的盾墙。双段怒技与剑势消耗规则不变。
- 卡面说明与公式测试同步更新，未手工修改编译 JSON，未调整已经认可的战斗布局或素材。

## 测量方法

`tests/shanhai-difficulty.mjs` 调用真实 `ShanhaiGame.create/dispatch` 与战斗引擎。
五门普通起始功法等量分层取样，每门一百种子，即每组五百局。
最终验收不使用离线敌方倍率，敌方参数全部来自 YAML。

`steady` 策略只看当前局面：缺血达到上限的18%时优先可达休整，
缺血达到20%且买得起恢复时优先可达坊市；否则偏好普通战。
事件只读取公开成本和已公开奖励，不读取线索型选项的隐藏结果、检定签或未来战斗。
采用固定天赋方案和现有奖励评分，不使用重铸、温养，也不进行全局路线搜索。
因此它是一个可复现的常规策略参照，不代表最优打法或真人的操作水平。

初版一百局参照为 100%、98%、98%、98%，原始记录保留在
`verification/shanhai/difficulty/baseline.json`。它的样本较少，
也早于运行时哈希字段的加入，只用于说明原先低损耗问题，不能冒充成对实验。

第一次五百局留出验证发现第四幕仍偏容易，因此已用于诊断，记录改存
`validation-v1.json`；虽然原始元数据保留 `split: holdout`，
**它不再是最终独立验收组**。后续高阶续航调整只在训练种子上比较，
最终另用全新的 `balance-release-20261023-holdout-*` 种子。
报告分别保存内容哈希、运行时与策略哈希、所有种子、死亡位置、回合数、净战损、
各功法表现，以及错误和未决，不从失败分母剔除难打的样本。

## 验收边界

每幕报告固定分母累计率、条件率和 Wilson 95% 区间。目标是校准参照，
不是保证任意五个固定种子都赢，也不是保证每门功法的通过率完全一致。
已有五门功法各自的合法四十五节点胜局夹具；这些精选种子只验证流程可通，
不纳入胜率证明。浏览器通关也使用明确功能种子，不给玩家临时加血、加装备或改结果。

## 最终结果

参数冻结后，训练组与全新留出组各五百局；各功法各一百局。
两组使用相同的内容与运行时/策略哈希，无离线倍率，无错误、无未决。

| 累计通过 | 目标 | 训练组 | 全新留出组 | 留出组 Wilson 95% 区间 |
| --- | ---: | ---: | ---: | --- |
| 第一幕 | 80% | 395/500，79.0% | 401/500，80.2% | 76.5%-83.5% |
| 第二幕 | 65% | 332/500，66.4% | 325/500，65.0% | 60.7%-69.1% |
| 第三幕 | 50% | 267/500，53.4% | 261/500，52.2% | 47.8%-56.5% |
| 第四幕 | 35% | 175/500，35.0% | 193/500，38.6% | 34.4%-42.9% |

四个目标均在留出组95%区间内。第四幕留出点估计仍高于目标3.6个百分点，
不能写成“实测恰好35%”。不再根据这批最终留出结果继续调参。
训练与留出合计一千局的累计率为79.6%、65.7%、52.8%、36.8%；
合计包含训练数据，不替代独立留出验证。

留出组逐幕条件通过率为80.2%、81.0%、80.3%、73.9%。
进入终战的一百九十三局中，一百七十四局获胜，入场后终战胜率为90.2%，
相对全部开局的最终通关率为34.8%。训练组对应为159/175、90.9%，
全部开局最终通关率31.8%。终战没有混入第四幕通过率。

## 复现

在仓库根运行：

```bash
npm ci
npm ci --prefix tools/content-kit
npm run build
npm run balance -- --seeds 100 --split train --seed-prefix balance-20261023 --policy steady --summary-only --output-file verification/shanhai/difficulty/train.json
npm run balance -- --seeds 100 --split holdout --seed-prefix balance-release-20261023 --policy steady --summary-only --output-file verification/shanhai/difficulty/holdout.json
```

`--seeds` 是每门功法的种子数，不是全组局数。
工具同时生成原始 JSON 和配套 `.json.md`；终战、未决、报错单列。
`--enemy-multipliers` 只供内存中的离线试算，不写回内容，也不接入游戏运行时。
原有 `npm run calibrate` 继续保留固定敌人参考盘和二十五局回归报告，
其小样本、多策略结果不替代这里的分层胜率验收。
