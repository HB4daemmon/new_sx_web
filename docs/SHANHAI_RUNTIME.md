# 山海版运行时说明

日期：2026-09-29。

## 边界

新版由 `src/shanhai/` 独立实现，现作为唯一游戏入口。编辑源为
`content/shanhai/`，构建不读取旧内容，也不迁移旧版存档。
内容库的 `status: design_target` 和 `balance.measured: null` 保持不变；
代码接线与自动测试不等于功法、敌人、法宝和四幕经济已经完成实测校准。

## 运行约定

- 两侧在轮初锁定动作与怒耗，执行时付怒，轮尾统一结算收入和削怒。
- 削怒先合并抗性并封顶 100%，向下取整，再应用轮内 20 或开场 50 的上限。
- 速度决定先后手，不增加主动作；多段有效直接攻击逐段产生受击回怒。
- 毒火独立记录每层快照与剩余 tick；派生伤害不能无限重复触发原事件。
- 同作用域的百分比增伤、造盾和盾返加成合加一次；系数增量、百分比和百分点分开读取。
  回春功的两阶怒技治疗增量可同时生效；溢疗出口的替代不重复消费同一份治疗。
- 盾返在首轮实现中是不暴击的固定派生伤害，受护盾吸收，不再经过目标防御；
  该交互与直接攻击区分，后续流派校准须单独观察。
- 首轮模拟窗口为 256 回合，僵持可按原输入继续推演到最多 4096 回合。
  上限不是失败判定；玩家可明确收手结束本局。15 回合只用于基线观察。
- 较长回放保留首尾记录并明确标记中间折叠；伤害、贡献和胜负仍由完整模拟结算。
- 存档保存战斗输入、种子和摘要，加载后确定性重建回放并比对胜负与余血。
  损坏或不匹配的存档报错，不自动清空。

## 界面与回放

界面保留山河、命盘、因缘导航、桌面人物侧栏、纵向地图和独立双人战斗舞台。
手机开局直接展示道号和命数输入，留空命数仍随机生成；功法详录按需展开。
奖励使用紧凑的横向三列，数字与关键机制在正文和详录中加粗着色。
奖励与天赋卡只保留概览和选择动作，完整效果使用统一详录弹窗；坊市可先查看法宝
再购买。命盘法宝默认显示短摘要，桌面侧栏的属性、构筑和持有法宝按需展开。
开局道号默认填入“无名行者”，留空或只输入空白时也使用该名，最多保留 24 个字符。
顶部和结算页的重开操作共用确认：确认后结束当前命途、清除本局存档与回放并返回开局；
通关构筑保留。首页存在旧局存档时，入山海同样需要确认，确认后按当前所选参数开始新局。
若清理存档失败，当前内存命途会保留并显示错误。
新命途、继续读档和回封面恢复页面顶部；同页操作保留滚动位置。关闭弹窗将焦点
返回原页面区域的入口，不能误落到另一处同名按钮或折叠内容中。
战斗默认只展示双方法相、姓名、血盾条、怒气条、短动作反馈与回放控制。
血盾同条分段显示，以气血上限加当前护盾作为展示容量，两个色段分别对应真实气血与护盾；
护盾数值显示为气血的加值，超过气血上限也完整计入，低血警示仍按真实气血比例判断。
这只改变显示方式，不改变最大气血、护盾吸收和怒气的结算规则。
构筑、状态、战报和贡献不再以内联折叠面板铺在战场，统一通过小按钮进入详情模态。
模态按我方、敌方、战报、战果分组，战前只提供双方资料；战报只显示当前已播放记录，
战果仅在回放完成或终局开放。天赋、法宝子详情关闭后返回原详情页签与入口焦点。
英文状态键、效果来源和卡面术语在展示层转为中文，不改战斗输入、种子或存档中的标识。
同一场战斗在原位更新立绘、血盾两段、怒气条与控件，不逐帧重建整个页面。
战报只在详情打开时渲染，切换简详模式、关闭重开后保留浏览位置与跟随状态。
普攻与怒技保留独立动作节拍，后续连续效果按动作及持续伤害阶段合并展示；
双方各自累计伤害、治疗、护盾吸收与生成，不用净值抵消治疗或将耗盾当作受伤。
合并反馈每方最多两条，四倍速也保留至少 400 毫秒的结果停留时间。
展示游标仍指向原始帧，详录保留全部已播放记录，不改原始帧或结算。
暂停、改速和切换战报模式不会重新触发当前帧动作；打开弹窗或离开战斗页会停止推进。
系统减少动态效果偏好会禁用位移和动画，保留数值、文字与静态状态反馈。

## 天赋与重选

- 天赋选择与随时可查看的天赋树共用四层三列展示，标明已悟、当前可选与未解锁；
  连线记录实际混选路径，不增加同列或前一项天赋的限制。
- 顶部天赋入口只读；查看未解锁天赋不授予能力，战斗中查看仍暂停回放。
- 普通坊市增加洗髓丹，每店一份，首测价格为 40 灵石，价格源位于 RULES 的
  `economy.non_artifact_prices.talent_reset`。购买前确认，购买即用，不另设物品背包。
- 只重选当前功法已经获得的 1..n 阶天赋，不增加境界、修为、回血或节点收益；
  其他功法选择和入节点快照保留，完成后回到原坊市，商品仍为售罄。
- 无已悟天赋时不能购买；重选中可存读档，不重复扣费、不提前发放未来境界天赋。

## 自由选路

- 新命途直接进入山河图，不选择整幕路线。每幕地图包含入口、九层三列分支和首领，
  共 29 个候选节点；实际每层走一个节点，仍为每幕 11 步，终局仅一场战斗。
- 邻列之间分叉与合流，玩家每次从当前相连节点中选择。进入后固定该节点，
  返回地图只恢复当前节点，不重抽事件、奖励或坊市。
- 地图及遭遇在入幕时冻结，刷新不会更换候选。`routeMap.nodes` 保存候选图，
  `routeMap.path` 保存已选节点键；`state.nodes` 仅保存已选路径，不再代表整幕预设路线。
- 商店、休整和精英可绕行，未走的节点不发收益；核心机缘仍受次数、间隔和前事约束。
  每幕第一场精英不占用全局额外精英额度。
- 之前山海运行时的线性存档保留已走及当前节点，未走的预设路线转换为分支地图；
  正在播放的战斗、领奖和突破状态保留。这不提供封神旧版存档兼容。

## 旅途解释

- 节点入口绑定当前功法和已有法宝。节点中新获得的旅途法宝不追溯触发。
- 养剑诀每完成两个合资格节点准备一份首击，独立于护盾；首击不增加主动作，
  不触发普攻完成或基础命中专属能力，下一场战斗消耗后不重复领取。
- 金乌真经的“开阔节点”在首轮实现中明确映射普通战、精英战、首领战。
  现有内容没有逐节点地形字段，不把商店、休整、事件或终战算为开阔节点。
- 烛龙真经的行旅交替序号与战斗昼夜分离。换法保留各自已选择天赋与行旅记录。
- 终战不发成长奖励，不触发额外旅途经济或免费恢复，只结算胜负与实际构筑记录。

## 验收边界

战斗回归覆盖精确怒气轮次、削怒顺序、DOT 快照、护盾、溢疗出口、
追击死亡边界、准备首击和条件替代。810 组天赋测试用于发现运行错误，
不代表每种构筑均已证明达到强度目标。

流程回归覆盖冻结掉落、商店重进、事件一次结算、非致命试炼、
换法与突破、每阶段存取和终战记录。另用真实战斗策略运行单局，
将实际失败、僵持和通关分别记录，不替换成桩胜利。

浏览器回归覆盖桌面和手机的开局、战斗播放、奖励读档、事件推进、
商店、休整、突破和终局归档。fixture 仅用于界面覆盖，不作为通关证明。

`npm run test:ui` 顺序执行经典界面、紧凑布局、重开与天赋树套件，报告默认保存在临时目录。
覆盖 320×760、360×780、390×844、1280×720、1440×900 等视口，检查首屏主操作、
节点预览无副作用、三列选择卡、字号、44px 触控区、导航遮挡、弹窗焦点和横向溢出。
天赋树套件另覆盖逐阶重选、洗髓丹确认与取消、中途读档，以及战斗中查阅天赋时暂停回放。
它需要先构建并启动游戏服务；浏览器验收期间不要并行重建正在服务的 `dist/`。
`npm run test:restart` 可单独验证默认姓名、重开确认与取消、存档删除失败保护、
战斗回放暂停恢复，以及重开后保留通关归档。

`test:journey` 另从创建角色开始，通过可见按钮完成桌面 45 节点与手机第一幕，
包括战斗暂停、继续、倍速、跳过、战斗与奖励刷新、终战存档和胜局归档。
它不修改角色属性、不伪造节点或胜负；截图用于留档，自动检查使用 DOM 和布局数据。

敌人已按公开配置完成首轮可玩性调整，未加入隐藏敌我倍率或免费恢复。
固定策略能否通关与难度是否达标分开判断；后期首领和终战偏短仍是当前主要平衡风险。
