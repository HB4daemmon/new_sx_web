# 从参考机制到修仙肉鸽构筑

日期：2026-10-26。性质：内部参考与 idea 发散，不是实装清单、平衡结果或新的系统合同。
用户要求这些资料只供设计参考；不复制名称、美术、文案或整套玩法，不要求所有金色天赋都复杂。
本轮没有修改游戏规则。万象棋原始资料另见[资料库](../wanxiangqi/README.md)。

## 1. 三类游戏分别提供什么启发

- 万象棋：一个天赋或棋手技能改变选取资源的理由，既有定流派，也有放大、转化和经营。
- 杀戮尖塔：资源的价值随已有构筑改变，代价能被另一件东西利用；简单遗物同样重要。
- 以撒：道具可以改变攻击的形态、频率、蓄力方式和触发效果，组合要在画面上看得出来。

以上是研究归纳，不是官方分类。共同目标不是增加系统数量，而是让玩家产生
“拿到这个以后，我开始想找以前不需要的东西”的念头。

## 2. 杀戮尖塔：查到的机制

限定为第一代，不混用《杀戮尖塔 2》。
[Snecko Eye 社区 Wiki](https://slaythespire.wiki.gg/wiki/Snecko_Eye)已读取到规则：
每回合额外抽两张牌，混乱使抽到的牌费用随机为 0 至 3。
其他条目采用社区数据项目的[固定提交快照][sts-data]，下表是规则概括，不是原文全量转载。
该快照没有标明客户端补丁号；部分 Wiki 请求受到限流后没有继续重试，
因此不宣称所有条目均经现行 Wiki 或客户端交叉确认。

| 条目 | 来源所载核心效果 | 设计上值得借鉴的点 |
| --- | --- | --- |
| Snecko Eye | 每回合多抽两张，战斗开始获得混乱 | 原本昂贵的牌可能更有价值；不是“随机越多越好” |
| Dead Branch | 消耗一张牌时，向手牌加入一张随机牌 | 一次资源消耗也可以生成新的行动可能 |
| Necronomicon | 每回合第一张费用至少为 2 的攻击牌打出两次；拾取时获得特殊诅咒 | 清晰条件下重演强动作，代价不必只写减伤或减攻 |
| Runic Pyramid | 回合结束不再弃掉手牌 | 改变资源的保留方式，进而改变组合兑现时机 |
| Brimstone | 自己回合开始获得 2 力量，所有敌人获得 1 力量 | 让战斗进入双方加速的竞赛，而不是无代价成长 |
| Membership Card | 商店商品半价 | 简单的经济放大就能让后续路线选择不同 |
| Kunai / Shuriken | 同回合每打出三张攻击牌，分别获得 1 敏捷 / 1 力量 | 行动次数形成成长轴；注意数的是出牌，不是命中段数 |
| Corruption，能力牌而非遗物 | 技能牌费用变为 0，使用后消耗 | 与 Dead Branch 组合后，技能消耗同时补充新牌；不保证无穷循环或生成指定牌 |

对本项目的限制：自动斗法没有手牌与手动出牌时机，不能直接塞入抽牌、留牌或零费牌。
借鉴的应是资源价值、有限重演、成长反馈和经营取舍，而不是把玩家无法操作的卡组藏在后台。
尖塔的 Brimstone 与下面以撒的同名道具并非同一规则。

## 3. 以撒：查到的机制

下表来自 IsaacGuru 条目，读取时网站明确标记为 **Repentance+**。
没有将它们标成早期 Repentance 的精确规则，也没有验证所有两两组合。
数值只用于说明来源，不是本项目拟采用参数。

| 条目与来源 | 来源所载核心效果 | 设计上值得借鉴的点 |
| --- | --- | --- |
| [Brimstone](https://isaacguru.com/item/c118) | 普通眼泪改为需要蓄力的贯穿光束，连续多次造成伤害 | 改变攻击形态和伤害节奏，不只是换特效 |
| [The Ludovico Technique](https://isaacguru.com/item/c329) | 改为一枚可操控的持续眼泪；弹速影响移动，射速影响命中频率 | 不同属性可在新形态下承担不同职责 |
| [Haemolacria](https://isaacguru.com/item/c531) | 抛物线眼泪命中或落地后裂成 6 至 11 枚小眼泪，同时改变伤害与射击延迟 | 大攻击可以分裂为多个仍有作用的小攻击 |
| [Tech X](https://isaacguru.com/item/c395) | 改为蓄力激光环；蓄力影响大小和伤害，外环持续伤害并贯穿 | “一次发射”与“多次命中”应当是不同概念 |
| [Anti-Gravity](https://isaacguru.com/item/c222) | 按住射击时眼泪悬停，松开或达到时限后发射 | 已生成攻击的释放方式也可以被改写 |
| [Chocolate Milk](https://isaacguru.com/item/c69) | 蓄力程度改变单发威力，页面范围为基础伤害的 10% 至 400% | 快而轻与慢而重不应只有外观差别 |
| [Habit](https://isaacguru.com/item/c156) | 受伤给主动道具增加 1 格充能 | 受伤可以成为有价值但有风险的输入 |
| [Soy Milk](https://isaacguru.com/item/c330) | 射速乘 5.5、伤害乘 0.2，并能自动蓄力发射部分蓄力攻击 | 极端交换可形成打法；形态变化还会影响其他道具 |
| [The D6](https://isaacguru.com/item/c105) | 将当前房间的道具重掷为该房间道具池中的其他道具 | 改变已见奖励的价值，而不是凭空保送指定配件 |
| [Steam Sale](https://isaacguru.com/item/c64) | 降低金钱商品价格，多份继续降价但收益递减 | 经营放大也能形成拿取偏好，不必新增战斗规则 |
| [Restock](https://isaacguru.com/item/c376) | 商店购买后补货；非 Greed 模式下，同一货位反复补货提高价格 | 商店由一次选购变成有限资金下的持续取舍 |

不可直接套用：单体自动斗法没有手动走位、瞄准、松开按键或房间障碍物。
不能因为原作激光环有空间优势，就认定本项目画一个光环也获得了相同的玩法。
攻击变形必须落实为段数、触发、耗费或时机的实际差异。

## 4. 原创候选池：先看改变什么选择

以下都是讨论候选，不是已经写入卡库的效果。动若脱兔与软猬甲来自用户先前举例，
不是在上述来源中找到的同名条目。数值、强度与最终名称均未确定。

| 候选 | 一句话规则方向 | 会变得值得拿的东西 | 战斗或旅途中可见的变化 |
| --- | --- | --- | --- |
| 动若脱兔 | 直接伤害随自身速度与敌方速度之比放大，设合理上限 | 加速、减速、先手爆发 | 同一招对慢敌更重，速度收益不再在抢到先手后停住 |
| 软猬甲 | 每次承受敌方有效直接攻击，增长本战防御并按防御反击 | 防御、减伤、恢复、承受多段的能力 | 被连续打时防御逐步爬升，反击随之变重 |
| 剑丸成阵 | 普攻改为多枚低单段伤害飞剑，分别结算命中型效果 | 命中施毒、命中成长、暴击、增加段数 | 剑阵的数量与每次命中效果都能看见，不是总伤害乘一下 |
| 归一剑意 | 把同次动作将要发出的多段与合格追击汇成一次重击 | 多段来源、单击增幅、破甲 | 同样的追加资源可以构成“一剑”，但放弃多次命中收益 |
| 身外化身 | 真身怒技后由化身以折减威力重演，保留明确允许的动作效果 | 怒技形态、返怒、状态附着 | 化身真实施法一次，不只是附加一条无形伤害 |
| 血战到底 | 敌我随轮次同时变强，己方成长更快 | 抢节奏、续航、关键轮爆发 | 越打越猛烈；不能只堆恢复无限拖延 |
| 无尽剑匣 | 剑阵消耗剑意时也能补充下一批剑意，提供有限延续 | 剑意生成、消耗收益、持续进攻 | 资源消耗后接上新一轮攻势；不是固定等待几场领奖 |
| 百炼成器 | 将选定的闲置普通法宝层炼入当前器物，立刻获得明确成长并失去材料 | 原本不合流派的奖励、额外掉落、熔炼服务 | 当次奖励就有价值，不追加延迟交付任务 |
| 市井仙缘 | 坊市每次买下一件商品后，当场补出一个同类商品；补货价格逐次提高 | 灵石、折扣、商店路线 | 一次入店可以持续调整构筑，但有限资金不能形成买卖套利 |
| 先天神力 | 直接获得显著攻击提升 | 多段、暴击及缺乏输出的任意构筑 | 简单、立即、有感；金色池应保留这种补强 |

这不是十套互斥职业，也不要求每件都占“核心位”。构筑核心、修饰、放大、转换和经营
是作用分类，不是品质分级；不同分类可以来自功法、天赋或法宝。

### 组合应能泛化，不只认固定配方

- 剑丸成阵搭配命中施毒是密集上毒，搭配命中成长则是快速起势。
  换掉配件，应改变实际结果；不是只有指定两件同名物品才触发隐藏套装。
- 剑丸成阵再配归一剑意，可以把“更多飞剑”变成一击蓄量。
  汇成一击后只发生一次实际命中，不能同时白拿所有多段触发收益。
- 软猬甲搭配恢复偏持久成长，搭配防御伤害放大偏主动反击。
  反击不再次触发反击，自伤、事件扣血与敌方受击必须分开。
- 身外化身可以重演不同怒技的动作，不能只适配一个指定功法。
  化身不能再生成同源化身，但其他合法命中效果不应一律被禁掉。
- 市井仙缘让经济资源改变找配件的机会，但不保证出现想要的核心，不通过读档重抽。

## 5. 对当前 V2 的底层启发

已读[当前 V2 基线](../../docs/shanhai/rework/V2_EXPERIMENT.md)。
当前实现确实存在一核心三辅器、回合初动作选择、双方按速度依次行动和轮尾结算怒气；
代码定位为 `src/shanhai/combat.ts` 的 `simulateBattle`、`executeAction`、`settleRage`。
这些现状不是错误，但不能仅靠增加几条伤害转换实现上面的全部候选。

1. **让属性在不同构筑里拥有不同价值。**
   动若脱兔可先用速度倍率表达，不必为了这个效果强行改成实时行动条。
   如果以后要让速度增加行动频率，需单独验证敌方节奏、控制和怒气，不能顺手夹带。
2. **分开行动、攻击段和派生效果。**
   “每次施法”“每次命中”“每次暴击”应当有真实区别。
   现有首段或每主动作一次的词条不能悄悄改成多段全触发，需要逐项标明并测试。
3. **允许有限的组合链，不靠全局每回合一次抹平差异。**
   明确每一环的资源消耗、来源和后代关系；相同来源不能沿自身输出无限重入。
   放行可以证明会终止的分裂、重演与成长组合；技术保险不能成为隐藏削弱。
4. **拿到新东西后的下一战就要有可辨变化。**
   剑数、化身、单击蓄量、防御成长与真实触发来源应与伤害帧一致。
   总伤害更高不自动等于玩家感知更好，也不能把来源伤害当成换装的净提升。

一核心三辅器是否过紧，需在真实组合试验后判断。先做出可泛化的机制，
再比较相同掉落条件下不同槽位的成型机会，不为看起来更像别的游戏盲目加槽位或系统。

## 6. 如何筛掉“听起来不错、玩起来没变化”

- 单件到手有作用，不能三件齐了才从零开始。
- 同一件至少能让两类已有资源产生不同搭配价值，而不只是提高总属性。
- 用同敌情、同基准随机条件比较空白、A、B、A+B，并查看逐帧触发，不只比较一次胜负。
  控制额外随机调用带来的差异，多种子复核；本轮没有完成这类战斗试验。
- 一次实际战斗中可以看出变化，精简卡面能说明玩家应期待什么。
- 保留强而直接的补强；不是全部金色都承担新流派，也不是所有差组合都要被系统修成强组合。

后续若进入实现，优先试验“用户提出的速度/防反”与“一项动作变形/重演”，
用小规模可玩对照检验方向，再扩展池子。此处不预设最终数量，也没有开始实现。
