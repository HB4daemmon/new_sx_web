# 修仙肉鸽机制研究索引

这是项目设计者的阅读索引，不是万象棋官方分类，也不是已实装清单。
原站完整规则见 [天赋](TALENTS.md)、[棋手](COMMANDERS.md) 和 [结构化快照](catalog.json)。
以下机制概括为研究归纳；具体条件、次数和数值以对应源条目为准。

## 当前设计原则

金色天赋可以独立撑起构筑，也可以承担转化、放大、稳定补强、旅途或资源经营。
不要求每张都复杂，更不应全部变成“把 A 转成 B”。
判断价值时看它是否让原本不想拿的资源变得值得拿，或让同一份资源有不同用法。

用户提出的“动若脱兔”（相对速度决定伤害倍率）和“软猬甲”（受击成长防御并反伤）
是本项目的设计输入。本次资料主表未检索到这两个名字，不能标记为已从原站验证的卡牌。
“黑洞”也未作为精确条目名检索到；可以研究混沌次元，但不擅自认定两者是同一机制。

## 天赋阅读线索

| 参考条目 | 原站机制的研究概括 | 对本项目值得讨论的点 |
| --- | --- | --- |
| [毒奶](TALENTS.md#talent-wanxiang-637010) | 特定二人共战改变施法目标及战斗行为 | 联动可以改变动作与目标，而不只是增加一条转化伤害 |
| [混沌次元](TALENTS.md#talent-wanxiang-681016) | 吞噬投入形成永久成长，再产生参战单位 | 无用资源能否成为主动投入；不直接照搬人口与召唤结构 |
| [身外身](TALENTS.md#talent-wanxiang-636604) | 技能附带化身攻击，胜利继续增长化身 | 一个清晰的成长轴能让玩家期待下一场 |
| [全副武装](TALENTS.md#talent-wanxiang-633020) | 达成装备条件后获得增伤与减伤 | 放大已有构筑，不必另发明一套复杂规则 |
| [全域共鸣](TALENTS.md#talent-wanxiang-636112) | 装备的专属效果扩大到其他使用者 | 打通功法或法宝限制，让原本不相关的物品变得有用 |
| [泉水](TALENTS.md#talent-wanxiang-632012) | 满生命时将恢复收益转向经验 | 健康局面下恢复资源仍有价值，但不能照搬每回合结算 |
| [无影手](TALENTS.md#talent-wanxiang-671018) | 提供有限的免费商店刷新 | 旅途天赋可以改变找到配件的方式，而不仅是增加钱 |
| [特大电池包](TALENTS.md#talent-wanxiang-635001) | 直接提供资源 | 简单且及时的补强也可以占据金色池，不必张张定流派 |
| [无限进步](TALENTS.md#talent-wanxiang-613011) | 成长资源在满级后改换收益出口 | 保证中后期拿到成长型天赋仍能发挥作用 |

“毒奶”的源条目不是“治疗量转为中毒层数”的规则。后续若做这种修仙版能力，
必须作为我们的新设计说明，不能用参考游戏的同名天赋为其背书。

## 棋手技能阅读线索

| 棋手 | 重点规则 | 可迁移的设计思路 |
| --- | --- | --- |
| [常小娥](COMMANDERS.md#commander-unspecified-commander-r11) | 小菟助力随使用次数成长 | 同一项操作的长期价值会变化，玩家会主动围绕它安排资源 |
| [镜](COMMANDERS.md#commander-unspecified-commander-r12) | 镜像复制上次打出的英雄牌，不能复制镜像牌 | 给玩家可控复制对象，同时明确排除自复制循环 |
| [明先生](COMMANDERS.md#commander-unspecified-commander-r10) | 卦象在刷新次数和能量之间取舍 | 出身能力可以改变经营方式，不必预先锁死战斗流派 |
| [姜导](COMMANDERS.md#commander-unspecified-commander-r17) | 钦定主角与后续永久成长强化 | 明确集中培养对象，使普通资源的价值随构筑改变 |
| [庄小鱼](COMMANDERS.md#commander-unspecified-commander-r5) | 根据阵容调整手牌或商店 | 提供定向找配件的机会，但不保证每局都拿齐最优组合 |
| [孙小宾](COMMANDERS.md#commander-unspecified-commander-r9) | 记录并重现出牌效果 | 可研究有限重演；必须分清主动行动与派生效果 |

棋手能力适合启发修仙版的先天命格或出身，但目前没有据此新增系统。
是否需要一个新选择层，要看能否带来不同经营方式，不能仅给现有天赋换个入口。

## 不直接照搬的部分

- 多人淘汰、人口、站位和阵营人数条件不能直接塞进当前单体自动斗法。
- 连败经营不能套进战败即结束的流程。
- 不增加用户已明确不喜欢的延迟领奖任务。可以借鉴成长逻辑，改为当次操作即时兑现。
- 单张参考条目不是强度证据；不把万象棋的数值比例当成本项目平衡参数。
- 本项目的转化、反伤、复制、成长都需要明确来源归属和循环边界。
  防止无限循环不等于把所有多段与连锁都限制成每回合一次。
