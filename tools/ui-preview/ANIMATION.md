# 完整人物逐帧动画

## 当前方案

2026-10-15 将独立 UI 预览的默认角色表现从刚性分片骨骼改为完整人物逐帧播放。
原因不是关节坐标是否接上，而是素材本身的头身比例、袖筒端盖和刚性拼接违和。
五种功法和养锋石卫均使用 `gpt-image-2.5` 参考编辑生成的十二张完整姿态，共 72 张。
每张都是重新绘制的完整人物，不是旧骨骼截图烘焙，也不是每秒 60 张独立手绘原画。
当前属于有限关键姿态动画；待机有轻微整体呼吸，动作以持帧和快速切换表达节奏。
新增造型与动作仍待用户视觉确认。

## 编辑源

- `src/frames-data.js`：十二个姿态索引、动作序列、持帧时长、命中点和纯时钟。
- `src/frames.js`：锁定版本的 PixiJS 逐帧播放器、纹理加载、暂停和生命周期。
- `public/assets/frames.json`：六套图集、固定锚点、裁切区域、来源和导出哈希。
- `public/assets/frames-{rkf01,rkf02,rkf03,rkf04,rkf05,en-a1-l1}.png`：六套公共图集。
- `prompts/combat-flipbook.txt`：共同生成提示词；`combat-frame-subjects.json`：各套身份与参考。
- `prompts/combat-stone-spacing.txt`：石卫间距修订，避免相邻剑尖与衣身连在一起。
- `scripts/prepare-combat-frames.py`：阈值清理原生 alpha、提取连通轮廓、固定比例导出。

本机原图保存在忽略目录 `output/imagegen/combat-frames/`。
剑修与石卫以已有完整人物主图为身份参考，其余四套以剑修主图的画法和各自旧图集的
身份为参考，重新绘制连续的衣身和肢体。各套颜色、武器和姿态不是程序换色。
来源原图不公开，不是运行或克隆后验收的必要条件；存在原图时额外校验其哈希。

使用技能自带 CLI，通过本机配置的接口执行 `gpt-image-2.5` 参考编辑。
未使用其他模型降级，未把 API 凭据写入仓库或提示词。
图集均为带原生 alpha 的 RGBA PNG。模型返回的透明像素仍可能保留背景 RGB，
不能把图像查看器展示的 RGB 当作不透明背景；导出时按 alpha 200 清理低透明雾边，
之后 Lanczos 缩放保留平滑轮廓。

## 帧与锚点

每套图集为 1200×1792，三列四行；每帧固定 400×448，脚底锚点 `[160,420]`。
十二个姿态依次为待机、预备、蓄力、命中、跟随、回收、怒技蓄力、怒技命中、
怒技跟随、格挡、法宝、恢复。
整套人物只用一个缩放比例，不按每帧包围盒自动放大缩小。
根据底部脚靴像素对齐站位；药杖与剑尖低于脚底的姿态有人工校准与额外画布留白。
提取按连通轮廓进行，不按名义网格生切；遮罩只保留该人物，避免跨格兵器带入邻人。

普攻播放待机、预备、蓄力、命中、跟随、回收、待机；怒技使用独立的蓄力、
命中和跟随图。法宝与恢复有各自手势。受击与格挡共用防御原画，但受击具有
独立的短时后退和回收，不能声称它们各有独立绘制的全套原画。
左右对手使用同一舞台比例与水平翻转，角色不带着 HUD 移动。

## 时钟与降级

`FrameTimeline` 用同一显式时间增量推进姿态与命中点，倍速只改变该增量。
普攻在第 19/60 秒进入命中图，怒技在第 26/60 秒进入命中图，每次只结算一次。
表现夹具仍负责伤害值、护盾优先和多段合并反馈，不改变正式游戏数据或模拟规则。
暂停、详情和后台状态冻结时钟与画布像素。减少动态时恢复静态待机，
提交一次尚未展示的命中；暂停状态下延后到恢复时提交。
离开斗法取消未完成动作，不结算已离开的反馈。
WebGL、纹理加载或上下文失败时回到原有全身插画；暂停中的未完成命中仍保留到恢复。

`public/rig.js` 是 `src/frames.js` 的可复现编译产物，不手工修改。
仅打包 PixiJS，不打包 DragonBones，不加载 CDN，也不放宽 CSP。
旧 `src/rig.js`、`src/rig-data.js` 和旧分层图集保留作参考与离线解析测试，
不是当前默认渲染器。旧 `check-animation-joints.mjs` 依赖旧画布接口，不再属于当前验收。
相关 MIT 声明保留在 `public/animation-LICENSE.txt`。

## 验收

在本模块执行：

```bash
npm run prepare:frames
npm run build:animation
npm test
npm run test:layout
npm run test:art
npm run test:surfaces
npm run test:rig
```

`prepare:frames` 需要本机忽略目录中的生成原图和 Pillow，其余命令不需要模型凭据。
`test:rig` 检查五种功法、六段行动、两侧真实像素、命中时机、暂停、倍速、详情、
低动效、离页与失败降级，并解码全部 72 张姿态，核对透明边距和不同姿态的真实像素。
逐动作渲染检查使用 320×568、390×844、1440×900 的真实角色区域大小，拒绝画布触边。
手机布局另覆盖 320×760。六套固定裁切比例的攻击与怒技接触表位于 `captures/frames/`。
主会话仍需查看实际手机和桌面画面；自动化通过不代表用户已批准美术。
