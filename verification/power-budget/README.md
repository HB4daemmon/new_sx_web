# 功法强度预算审计

这是一个短小、无安装依赖的预算算术检查器。它使用 Node 内置 `assert`，只检查统一
参照下的输出/承伤/最大气血预算，不模拟伤害、命中、状态、胜负或死亡流程。

## 运行

在仓库根目录执行：

```sh
node --check verification/power-budget/audit.mjs
node verification/power-budget/audit.mjs
```

脚本还导入 `verification/rage-economy/audit.mjs` 的 `runScenario` 和 `makePath`，用
15 回合、双方每轮一段有效敌方主动直接段的统一输入核对资源动作数。当前文件保持短小，
不再复制一套战斗或资源引擎。

## 主合同

统一普通参照取输出 `D=100`、净有效生命损耗 `L=100`、最大气血指数 `H=100`。完整存活
且 `L>0` 时才可评分：

```text
P = D * H / L
```

`L<=0` 或提前结束的盘不能返回 `Infinity` 或高分，审计器会拒绝评分，另行处理。`D=0`
保持原始的 `0`，不会为每门功法单独重新归一化成 `100`。这里的 `D/L/H` 都是相对同一
普通参照的指数，不是运行时伤害或生命值。

每阶使用初始 25 点的线性成长，不复利：

| 稀有度 | n=0 | n=1 | n=2 | n=3 | n=4 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通 | 100 | 125 | 150 | 175 | 200 |
| 稀有 | 110 | 137.5 | 165 | 192.5 | 220 |
| 传奇 | 125 | 156.25 | 187.5 | 218.75 | 250 |

稀有度只应用一次总预算 `1 / 1.1 / 1.25`。不能把攻击和生存各自加 10% 后得到
`121`，再把结果称作稀有 `110`。六层普通装备或传奇装备不隐含在基础盘；本审计不
计装备，只核对天赋本体预算。

## 算术边界

- 纯防御保持 `D=100,H=100` 时，`L=100,80,66.6667,57.1429,50` 对应约
  `P=100,125,150,175,200`。
- `L=75` 对应 `P=133.333...`，不是 `125`。
- 混合 `D=110,L=88,H=100` 为 `125`；`D=100,L=100,H=125` 也为 `125`。
- 十门基础目标是预算目标而非测量结果：金刚 `90/90/100=100`，归元
  `100/100/100=100`，回春 `85/85/100=100`，御火与养剑均为 `100/100/100=100`；
  五毒 `104.5/95/100=110`，奔雷 `110/100/100=110`，太阴 `99/90/100=110`，
  金乌 `125/100/100=125`，烛龙 `112.5/90/100=125`。

## 资源示意

15 回合实际动作数由 rage 审计核对为：

- 普通无归元固有：普攻 11、怒技 4，节奏为 `3/7/11/15`。
- 归元固有：普攻 10、怒技 5，节奏为 `3/6/9/12/15`。
- 仅 J1A：普攻 10、怒技 5，节奏为 `2/5/8/11/14`。
- J1A + J2C：普攻 8、怒技 7，节奏为 `2/4/6/8/10/12/14`。

下面都是示意伤害数，不是正式功法倍率：

- 普攻 4、怒技 14 时，普通动作数给出 `11*4 + 4*14 = 100`。
- 多 1 次怒技替代 1 次普攻只增加 `14-4 = 10`。
- 在 4 次怒技不变时，若总输出只需增加 25，每次怒技需增加 `25/4 = 6.25`。
- 归元普攻 4、怒技 12 时，`10*4 + 5*12 = 100`；仅 J1A 仍是 100；
  中投入动作数给出 `8*4 + 7*12 = 116`，不能直接宣称达到 150。

资源加速改变普攻/怒技占比，但不能直接换算成天赋达到 25 点成长；完整伤害倍率、状态
覆盖、存活与装备预算仍需另做平衡验证。

## 效果台账 fixture

`effects.mjs` 与 `effects-audit.mjs` 是本目录的独立确定性效果层。它们不修改运行时，也
不把样例结果写入功法、法宝或正式 `D0/L0/H0`。效果层只做有限输入的逐事件复算，当前
覆盖：

- 有效气血、护盾和治疗台账：外来实际入血、自伤、有效自疗、溢出唯一出口，以及盾的生成、
  实际吸收、主动消费、过期和剩余守恒。护盾吸收不再在 `L` 中重复扣。
- 有序事件 ledger：每条记录保留根来源、动作、段、时间和派生链；角色死亡后立即跳过
  后续伤害、治疗、状态和 DOT。
- 有限 DOT：snapshot/dynamic 两种显式读值、有限 tick、叠层上限、刷新、过期、消费和
  移除。窗口末或死亡后未兑现的 tick 单列为 `unfulfilled`，不进入 `D`。
- buff/debuff 的实际作用结果：状态标签本身没有分数；只有实际读取并改写结果的状态进入
  覆盖分子。覆盖支持攻击者的前置 `attack-attribute`、后置 `outgoing-damage`、虚弱，
  以及目标的破甲；`qualified-events` 同时报告合格事件分母和按原始输出量加权的分母。
  同一 `coverageKey` 的多个状态逐条保留，不合并后重复累加；`buffEligible:false`、过滤
  不符或公式没有显式读取对应状态的事件不计入。
- 3/5/10/15 检查点、有效/浪费、状态层数与覆盖结果；检查点超出 `actualTime`、窗口或
  提前终止时返回 `available:false`、数值 `null` 和原因。`result()` 是纯快照，不会把
  当前状态自动推进到窗口末；需要完整测试窗时必须显式加入 `advance` 事件到 `window`。
  `powerScore` 仍拒绝 `L<=0` 或提前结束样本，不能用早死或无损样本制造 `P`。

fixture 可通过 `formula: {type: "subtract"|"ratio"}` 或显式 `damageFunction` 指定
简单伤害函数。`subtract` 与 `ratio` 只是本 fixture 的显式公式，不是项目正式减伤式；
公式中的 `weakness` 表示攻击者攻击输入按比例减少（范围 `0..1`），破甲读取目标，
前置攻击属性修正只有在公式明确写 `readsAttack:true`（或等价读取声明）时才生效，
同类攻击增加/降低先合并再经过防御，后置 `outgoing-damage` 才在公式结果之后作用。
这保证攻击属性不会放大未读取攻击的显式 `amount` 或 DOT。破甲、虚弱、护盾加成、DOT
时长和系数都是测试输入，不是项目已确定的全局减伤式、抗性或毒火穿盾规则；未声明的抗性不会自动生效。治疗先拆成有效部分与溢出，
有效治疗转盾和溢出转盾读取不同资源，只各享一次明示的护盾加成，不能重复放大同一份治疗。

效果结果中的 `D_raw`、`L_raw` 是原始 fixture 数量：分别表示敌方实际有效伤害（含敌盾
真实消耗）与净有效生命损耗。为兼容旧审计仍保留同名 `D`、`L`，但它们也只是 raw 数量，
不能直接传给正式 `powerScore`；`units` 明确标记其单位。正式归一化指数 `D/L/H` 仍由
共享参照和 `audit.mjs` 单独计算。

`toRageRoundInputs()` 只桥接三类有限输入：有效敌方主动直接受击段、由
`sourceRole:"self"` 造成敌方正 `hpDamage` 的 DOT、以及带明确 `actor:"self"` 和
`triggerContext:"main-action"`（或合法派生上下文）的有效自疗。满血溢出、敌方赠疗、
战外治疗、敌方/他方 DOT、仅吸收敌盾的 DOT 都不授予输入。死亡或敌方终止会在终止轮写入
`battleContinues:false`；`runScenario` 会保留该轮待结算收入用于审计并丢弃，不继续后续
轮次。RR08/09 等真实掉血/盾返来源没有在这个静态适配器中伪造，仍未桥接。

运行新增效果审计：

```sh
node --check verification/power-budget/effects.mjs
node --check verification/power-budget/effects-audit.mjs
node verification/power-budget/effects-audit.mjs
node verification/power-budget/effects-audit.mjs --json
```

本审计保留既有 `audit.mjs` 的算术检查和 `verification/rage-economy/audit.mjs` 的资源
检查；通过数量只表示这些确定性 fixture 通过，不表示全卡强度达标或正式平衡完成。

### 未覆盖边界

- 不替代真实运行时的命中、暴击、AI、先后手、胜负、存档或全量功法/法宝引擎。
- 不声称覆盖全部卡牌、概率 AI、动态敌方动作重算或削怒后的真实胜负；静态 rage 适配器
  只验证上述三类有限输入。
- 不擅自决定全局防御、毒火穿盾、抗性、状态时长、叠层策略或正式倍率；每个 fixture 必须
  显式传入这些输入。
- 敌人死亡记为 `earlyEnd:"victory"`，自身死亡记为 `earlyEnd:"death"`；二者都
  `complete:false`，终止时不发出后续效果，但保留剩余状态作为 `unfulfilled` 资产。
- 不把状态剩余、期末护盾、未兑现 DOT、速度或回怒数值直接折算成 `D/L/P`；完整十五回合
  （显式 `advance` 到窗口）和真实对手压力盘仍需独立运行时 fixture。
