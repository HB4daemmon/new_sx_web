# 怒气资源审计

这是一个独立、可复算、无安装依赖的 Node.js 资源审计器。它只核算双人资源，不接
运行时，不模拟伤害、命中概率、胜负、死亡原因或眩晕控制。

## 运行

在仓库根目录执行：

```sh
node verification/rage-economy/audit.mjs
```

脚本使用 Node 内置 `assert`，运行时会打印核心节奏表、检查数和 `PASS` 计数。当前审计
包含 62 项检查，其中 54 个是双向资源场景；每个场景都以 `A -> B` 和 `B -> A` 两种
执行顺序运行，并比较完整的逐回合已结算 trace，另外 8 项是公式、快照或路径边界检查。
改变先后手不能改变已锁定动作、支付、待结算收入、削怒合并或轮尾结果。

`audit.mjs` 同时导出以下纯函数/类，便于后续验证复用：

- `RageBattle`：逐步执行 `initialize`、`lockRound`、`executeRound`、`settleRound`。
- `runScenario`：一次性运行确定性场景。
- `RageBattle#snapshot` / `restoreBattle`：保存和恢复最小中途状态。
- `resolveDrain`、`settleFormula`：独立复算削怒与轮尾公式。
- `makePath`：生成归元路径的资源部分，包含固有返怒、J1/J2/J4 入口和 RC 层数校验。

## 口径

审计器使用以下固定资源合同：

- 基础上限 `100`，配置下限 `60`；怒气下界为 `0`。
- 基础入战怒气 `50`。入战额外回怒和对手开场削怒先合并，开场削怒最多按 `50` 计，
  再一次性计算：
  `start = min(cap, max(0, 50 + openingBonus - min(50, floor(requests * (1 - resistance)))))`。
- 每次普攻主动作完成待结算 `+25`；怒技不领取这份普攻收入。
- RR01 的基础攻击有效命中额外回怒按每个普攻或怒技主动作最多一次登记 `+10`。输入
  字段是 `baseAttackEffectiveHits`；`basicEffectiveHits` 保留给只读取普攻的 RR13/J2A
  削怒请求，不能用它把怒技伪装成普攻命中。旧配置中的 `sources.basicHitRefund` 仍是
  兼容别名，审计内部统一登记为 `base-attack-hit-refund`。
- 每个有效敌方主动直接段待结算 `+5`。同一段同时有正护盾吸收和正气血伤害只算一次；
  零伤害、闪避、毒火、反震、自伤和事件扣血不算。
- 每整轮末自然 `+10`。普攻额外回怒、轮尾额外回怒、固定返怒和条件回怒也都先记为
  本轮待结算值。
- 每轮初用上轮已结算怒气锁定双方动作及怒技成本。满怒时若有强制普攻仍先锁普攻；
  怒技执行时按锁定成本支付一次。轮内新收入和新削怒不改变已锁定动作。
- 轮尾先应用当轮临时上限变化，再计算：
  `B = roundStartRage - actualPaid + allPendingIncome`
  `D = min(20, floor(sumDrainAfterResistance))`
  `end = min(cap, max(0, B - D))`。
  不能先把 `B` 截到上限再削怒；例如 `B=130`、削怒 `20`、上限 `100` 时结果是
  `100`，不是 `80`。
- 同类抗性先相加并限制在 `0..1`。比例返怒按本轮实际支付金额计算，同类比例先合计，
  最后只向下取整一次；固定返怒允许相加。收入不会制造额外主动作。
- 死亡或终战轮不把待结算收入带出场。审计器仍把这轮登记值保留在 trace 中，标记
  `settled: false` 和 `discardedPendingIncome`，用于检查是否错误发放。

## 场景覆盖

核心表包括：

- 18/20 轮一段有效受击基线：首怒 `3/7/11`，前七轮尾值
  `90/100/15/55/95/100/15`。
- 无受击 `3/7`、每轮两段 `3/6`、每轮三段 `2/5`。
- RC19 上限 `-5/-10/-15`、RC20 普攻额外 `+5/+10/+15`、RC21 轮尾额外
  `+5/+10/+15`、RC22 开场额外 `+15/+30/+45`、RC23 固定返
  `+5/+10/+15`，以及 RC24 每有效受击段额外 `+2` 的逐段计数。
- RR01、RR07、RR08、RR09、RR10、RR11、RR12。条件来源必须通过显式回合输入触发，
  不会被审计器当成每轮默认发生；RR01 可分别核对普攻和怒技的基础攻击命中，追击、
  毒火和其它事件不会冒充该字段；RR10 每个自身动作最多读取两次有效直接暴击。
- RL04 开场额外 `+50`、RL05 固定返 `+50`、归元基础返率 `20%`。
- `makePath` 的每条归元路径都保留固有返率 `20%`；J1A 为上限 `-10`，J1B 为普攻
  额外 `+10`，J2A 为基础攻击有效命中额外 `+10`，J2B 为轮尾 `+10`，J2C 为返率
  增加 20 个百分点。J4A 再增加 20 个百分点；J4C 已建模为怒技后下一轮强制一次普攻，
  该次基础积怒为 `25+15=40`，与 J1B 合法相加且不放大其它法宝收入。
- 中投入 `J1A + J2C`：上限 `90`、总返率 `40%`，首怒 `2/4/6`。
- 高投入在中投入上增加 `J4A`、RC21 三层、RC23 三层：总返率 `60%`，首怒 `2/3/4`；
  怒技轮收入实算为 `54 + (自然10 + 固定返15) + 轮尾额外15 + 受击5 = 99`。
- J1/J2/J4 各层只能选一个选项；RC21、RC23 层数必须是 `0..3` 的整数，J2 多选和
  超过三层都会明确失败。
- 截脉针 RR13 与太阴 J2A 各一份基本命中削怒请求时，合法合计为 `20`；RR15
  `50%` 抗削怒按请求类型处理。另有每轮固定 `20` 的最坏压力注入，用来核对裸配置
  `4/10/16`、高投入 `3/5/7`，以及轮尾额外 `20` 抵消压力后恢复 `3/7`。
- 多来源削怒统一受 `20` 上限约束，不按来源或攻击段重复突破；开场 `+50` 与敌方
  开场 `-30` 的顺序也经过双向场景核对。
- 强制普攻满怒、锁定怒技后同轮削怒、回元佩旧成本支付后再降上限、固定/比例返怒不
  重复发放、0 下界、入战只初始化一次、有效段过滤和最小读档恢复。

## 输入假设与边界

`RageBattle` 的条件来源不猜测战斗结果。回合输入只提供已经由上层战斗规则确认的事件，
例如：

- `incomingSegments`：有效敌方主动直接段及其 `hpDamage` / `shieldAbsorbed`；
- `baseAttackEffectiveHits`：本回合当前普攻或怒技的基础攻击直接段是否有效命中；
  RR01 每个主动作最多读取一次，追加、追击、毒火和其它派生不由该字段自动推导。
- `basicEffectiveHits`：本回合是否有普攻基础段有效命中；它只在普攻动作上触发
  `basicDrainSources`（RR13/J2A），怒技输入不会读取它；
- `trueEnemyHpLossActions`、`effectiveShieldReturnActions`、`directCrits`、
  `poisonFireTicks`、`selfHealActions`：RR08/09/10/11/12 的已确认触发次数；
- `drainRequests`：已确认进入本轮的外来削怒请求；
- `battleContinues: false`：显式表示死亡或终战，用于验证待收入丢弃。

因此本模块不回答“这次攻击是否命中”“伤害能否杀死角色”“眩晕是否永久成立”，也不
宣称资源循环已经完成战斗平衡。它只证明资源账本、来源边界、回合窗口和合并顺序。

快照包含当前双方的锁定动作、锁定成本、实际支付、待结算收入、待结算削怒、临时上限
变化和完整 trace，覆盖最小中途恢复场景。它不是运行时存档格式兼容性测试，也不替代
运行时真正的读档迁移、死亡流程和胜负结算验收。
