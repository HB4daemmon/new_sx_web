# Adventure Budget Audit

这是一个独立的设计 target 节点算例。它只做路线计数约束、名义法宝机会和
post-acquisition 资源台账，不导入游戏运行时，不实现敌人伤害、命中、战斗胜负或
44 卡平衡。`loss` 是 fixture 明确提供的外部净损耗输入，不是由配装推导出的实测值。

## 运行

在仓库根目录执行：

```sh
node --check verification/adventure-budget/audit.mjs
node verification/adventure-budget/audit.mjs
node verification/adventure-budget/audit.mjs --json
```

普通输出报告检查组数、通过数和基准 fixture 汇总；`--json` 输出机器可读报告。任何
失败都会以 exit 1 结束；作为模块导入时不会打印。脚本仅依赖 Node 内置模块，并直接
复用 `verification/artifact-budget/audit.mjs` 的 `RARITY_BUDGET` 与
`nominalOfferBudget`，不会复制另一套稀有度预算。

## 真正覆盖

- `validateRoute` 校验六种 11 节点路径：每幕恰好一个 `B` 且位于末尾，每幕至少 3 个 `C`，
  `extraL = max(0, L - 1)` 每幕最多 1。四幕校验还限制普通 `C + E >= 22`、
  全局 `K <= 3`、每幕最多一个 `K`，并要求相邻 `K` 之间至少有两个非 `K` 节点。
  节点 ID 必须唯一。支持一至四幕的部分路径计数，全局普通节点下限仅在四幕时检查。
  `makeFullRoute` 生成四幕加单独末尾 `F` 的 fixture，`F` 只能出现在四幕之后。
- `validateFinale` 检查最终节点是 `F`，无新候选、掉落、治疗、灵石、修为、商店或准备；
  不支持的附加字段会拒绝。终战没有奖励，也不能通过显式 event 在终战追加补给。
- `routeBudget` 根据给定六路径的实际 C/L/B 计数和共享位阶尺计算名义战斗法宝机会
  `8.8 / 10.2 / 8.8 / 8.8 / 8.8 / 7.4`，并把事件赠予与事件购买的 B 分列。
  `bossCombatBudget()` 返回战前累计 `6.4 / 15.2 / 24 / 32.8` 和战后累计
  `8.8 / 17.6 / 26.4 / 35.2`；数值来自共享 `nominalOfferBudget`，没有复制 B。
- `makePostAcquisitionFixture` / `settleAdventure` 使用四幕基准路径
  `C E C R E S C E C L B` 加 `F`。初始 HP/maxHP 为 `200/200`、coins 为 20、
  XP 为 0、`n` 为 0；XP 需求是 `[120, 480, 600, 840]`。每个战斗节点的
  `loss`、治疗原始量和 XP 都是显式 fixture 输入。
- `settleAdventure` 仅结算四幕加终战的完整 fixture。奖励顺序是：记录 `before`，
  消费支持的显式事件，应用外部 loss，记录尚未获得奖励的
  `after`，确认存活后才结算金币、法宝、治疗和 XP；`settled` 是结算后快照。
  每个 `E` 只兑现一个选择：幕内节点 2 普通一层、节点 5 的 20 灵石、节点 8 原始治疗 40。每个
  `S` 付 40 coins 后获得一个普通；每个 `C/L/B` 分别获得
  `+4/+6/+10 coins` 和普通/稀有；`F` 没有奖励。
- 基准结果核对：每幕 B 后 HP `[138,138,138,138]`，F 后 94；外部净损耗 388；
  原始治疗 `360`、有效 `282`、浪费 `78`；XP 每幕
  `[460,600,750,900]`，累计 `[460,1060,1810,2710]`，突破发生在全局节点
  `3/14/25/36`，最终余 `670` 明确不可用且无下一境界；每幕末 coins
  `[32,44,56,68]`，末币 fixture 的 `usable` 为 0；common 24、rare 8，
  总取得名义 B 为 43.2，其中战斗掉落、事件赠予、事件购买分列，购买所用 coins
  不再次作为免费 B。
- `plannedCombatB` 记录计划机会，`combatB` 只累计存活结算后实际取得的战斗法宝；
  计数按件数而不是发奖节点数相加。初始持有量另列，不冒充本次取得。
  外部 `loss` 请求、实际扣除的 HP 与整条路径计划输入也分列，超额致死不计作实际扣血。
  `eventDamage` 单列主动血价，`hpCapLoss` 单列降低生命上限造成的当前血量截断，
  不混入敌方外部损耗。`xpByAct` 汇总所有实际结算修为，而非只统计战斗节点。
- `applyAdventureEvent` 可独立检查主动扣血、购买、最大 HP 变化和非致命挑战声明。
  主动扣血后的 HP 必须严格大于 0；恰好归零会拒绝。挑战只保存输入并标记
  `simulated:false`，不模拟胜负。购买按当前 coins 顺序结算，不预支后段收入。
  `applyMaxHpChange` 的上限增长不增加当前 HP，上限降低才会 clamp 当前 HP，新上限必须大于 0。
  完整账本只通过 `S` 节点购买；额外插入的 purchase event 会被拒绝，避免漏记购买来源。
  `S` 固定只兑换一层普通法宝，不接受额外夹带奖励或治疗。
- `makePostAcquisitionFixture({skipR:true})` 用无治疗 `E` 替代全部 `R`，其余输入不变。
  结果为幕末 HP `[138,92,46,0]`，在第 44 个节点 B 死亡；该 B 无奖励，不能进入 F。
  死亡后所有后续节点和奖励停止。未知、缺失或非数值 loss、重复 ID、terminal 额外
  奖励、多分支同时发奖、购买不足都会拒绝或返回带原因的失败结果。
- 初始状态不得用显式 `null` 冒充默认值；境界必须在 `n0-n4` 内且与累计修为一致。
  负生命、零生命起步、非整数物品数或无效最大生命会拒绝。满阶后即便尚未到 F，
  下一境界仍是 `none`，可继续用于突破的修为为 0。
- 所有结果保留 `target`、`example_only`、`measured:null` 字段，避免把设计算例、
  外部损耗或名义 B 写成实测、胜率或运行时通关证据。

## 未覆盖

- 不解析完整运行时 schema，不验证四套敌人配置合法性；这些配置仍需独立内容核验。
- 不验证地图分叉可达性、替换来源、人物线资格或重入幂等。路径计数通过不等于地图生成正确。
- 事件选择只覆盖本算例的普通法宝/灵石/治疗三分支，不代表所有普通事件都必须三选一。
  一般事件仍可提供两至三个选项；法本、核心奖励等不由此脚本模拟。
- 仅接受有限且非负的外部净损耗；战斗结束比开战时生命更高的净恢复情形尚未建模。
  非致命挑战仅登记声明，不生成其战斗或奖励。所有计划节点的损耗必须明确，
  即使玩家提前死亡，后续未知损耗也不默认成 0。
- 不实现伤害公式、敌人行为、命中、暴击、装备触发、状态、事件胜负、AI、路线随机
  生成或真实商店库存。
- 不从 `loss` 反推法宝强度，也不把 XP、治疗、金币或 B 总量换算为胜率、通关率或
  全卡平衡结论。最终 `F` 无候选、无新法宝，不存在未模拟的“神话奖励”。
